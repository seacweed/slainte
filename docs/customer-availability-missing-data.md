# 손님 등장 조건 누락 데이터

기준 자료:

- `Data_slainte.csv - 손님 (1).csv`
- `[슬런챠]개발 기획.md`
- `[슬런챠]개발 기획 (1).md`
- `[슬런챠]개발 기획 (2).md`
- `[슬런챠]개발 기획 (3).md`

## 현재 반영된 내용

- CSV의 유효 방문 41개를 손님 방문 데이터베이스에 등록했다.
- `등장 확률` 5/3/1을 상대 가중치로 저장한다.
- 시작 상태에서는 `근로자들`, `F54`만 활성화한다.
- `StrangeCoin_0` 완료 후 `아무개들`, `F72`를 활성화한다.
- `sc2_1_false`가 설정되면 `아무개들`, `F72`를 비활성화한다.
- `sc2_1_true`가 설정되면 `셀리`를 활성화한다.
- `StrangeCoin_3` 완료 후 `E12`를 활성화한다.
- `tl3_2_1_true`, `tl3_2_2_true`에 대응하는 카사 방문형을 등록했다.
- 맛과 분위기는 원문 데이터만 보존하고 아직 추첨에 사용하지 않는다.

## 에피소드 및 플래그 누락

다음 기획명에 대응하는 실제 `EpisodeData.episodeId`가 현재 프로젝트에 없다.

- 아이들 0, 1, 3
- 말하는 기계 0, 3, 4
- 야간 순찰 이벤트

다음 분기 플래그는 기획 문서에는 있으나 현재 에피소드 데이터에서 설정되지 않는다.

- `sc2_1_true`
- `sc2_1_false`
- `tl3_2_1_true`
- `tl3_2_2_true`

에피소드 데이터가 추가되면 기존 손님 활성 상태 전환 조건에 실제 ID와 플래그를 연결해야 한다.

## 확인이 필요한 기획

- 야간 순찰 문서의 `if F54 on` 항목이 두 번 반복되어 있다. 중복인지 다른 조건의 오기인지 확인이 필요하다.
- 맛/분위기 선호가 주문 후보 가중치, 손님 만족도 또는 대사에 어떤 영향을 주는지 규칙이 없다.
- 손님별 최초 등장 일차가 아직 없다.
- 손님별 주문 및 반응 대사가 아직 완성되지 않았다. 현재는 기본 주문/반응 표시를 사용한다.

## 이미지 누락

현재 다음 캐릭터는 표시용 이미지가 없다.

- `big_fish`
- `n8`
- `eric`
- `cartha`
- `eliud`
- `e43`

`eric`은 시작 손님군이지만 이미지가 없어 임포터가 임시로 시작 비활성화한다. 이미지가 연결된 뒤 다시 임포트하면 시작 활성 상태로 복구된다. 나머지는 현재 시작 조건에서 비활성 상태다.

## 레시피 연결 누락

여러 손님의 기획 주문명 중 일부는 현재 레시피 데이터와 이름이 일치하지 않는다. 각 방문에는 연결된 주문이 최소 1개 이상 있으므로 플레이는 가능하지만, 누락된 레시피가 추가되면 손님 CSV를 다시 임포트해야 한다.

CSV에서 ID가 없는 마지막 설명 행은 손님 데이터가 아니므로 경고만 기록하고 건너뛴다.
