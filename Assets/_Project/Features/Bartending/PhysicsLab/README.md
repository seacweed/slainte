# 슬롯 없는 바텐딩 물리 샌드박스

기존 게임플레이와 분리한 병·잔·도구 프리팹 실험 환경이다. 기존 컨트롤러, 슬롯, 액체 풀, GPU 싱글턴, 제작/영업 시스템과 씬은 수정하지 않는다. 기존 ItemDef, GlassDef, ToolDef와 그림은 읽기 전용 원본으로 사용한다.

## 실행

`Scenes/BartendingPhysicsSandbox.unity`를 열어 Play하거나 `Slainte > Physics Lab > Create or Open Sandbox` 메뉴를 선택한다. 프리팹 24개(병 15, 잔 4, 도구 4, 얼음 1)가 `Prefabs/`에 있다. 씬에는 병 3개, 잔 2개, 도구 4개가 배치된다. Build Settings에 기존 씬을 추가하거나 바꾸지 않는다.

| 조작 | 동작 |
| --- | --- |
| 좌클릭 | 집을 때 현재 위치에서 각도 0도로 초기화 / 내려놓기. 클릭 전 최근 이동 속도로 던지기 |
| 우클릭 + 마우스 상하 이동 | 잡은 물체 회전. 양방향 여러 바퀴 허용 |
| 우클릭 해제 | 현재 위치에서 약 0.15초 동안 각도만 0도로 복귀. 커서도 잡은 지점을 따라 이동 |
| 천천히 다른 물체 위에서 내려놓기 | 두 물체 위치 스왑. 원래 각도와 내용물 소유자 유지 |
| C | 잡은 셰이커의 덮개 열기/닫기 |
| R | 테스트 세션 전체 재시작(재고·생성 얼음·GPU 버퍼 포함) |

집을 때 현재 위치에서 즉시 0도로 초기화하고, 우클릭을 놓으면 현재 위치에서 빠르게 0도로 복귀한다. 병·잔·도구·얼음에 공통 적용한다. 복귀 시간은 Interactor의 `uprightReturnDuration`으로 조절한다(기본 0.15초). 복귀 중 커서는 잡은 지점을 따라가며, 마지막 커서 이동을 확인한 다음 드래그를 재개한다. 이동을 확인하지 못하면 현재 커서에 맞춰 잡기 오프셋을 보정한다. 자동 복귀 움직임은 투척 속도에 포함하지 않는다. 회전/복귀 중 다시 우클릭하면 현재 각도에서 수동 회전을 시작하고, 좌클릭으로 물체 자체를 놓으면 그때의 기울기를 유지한다. R은 검증용 전체 세션 초기화다. 겹침을 해소할 수 없는 위치에서는 내려놓기/스왑을 취소하고 계속 잡고 있는다.

## 동작 및 구조

- 모든 물체와 테이블은 숫자 레이어 29를 사용한다. TagManager나 전역 충돌 행렬을 변경하지 않는다.
- 놓인 물체는 Rigidbody2D Dynamic이며 병, 잔, 도구끼리 부딪혀 밀리고 쓰러진다. 잡은 물체는 Kinematic으로 이동하며 다른 큰 물체/테이블과의 충돌을 일시 무시한다. 얼음은 잡은 잔과도 물리 충돌한다.
- 병의 주둥이 방향과 실제 자세로 쏟기를 판단한다. 손을 놓은 병도 기울어져 있으면 흐른다. GPU가 입자를 수락한 양만 병 재고에서 차감한다. 움직이는 주둥이의 속도를 방출 입자에 전달한다.
- 병의 방출은 `PhysicsLabBody.Pouring.cs`에서 처리한다. 콜라이더 중심→입구 방향을 기본값으로 사용하며, 생성점은 입자 반경을 포함한 병의 박스 경계 밖으로 보정한다. 기울기에 따른 유량은 시작 각도에서 0, 최대 각도에서 1인 Smoothstep 곡선이다. 기본 각도는 90/120도다.
- 누적 유량으로 물리 주기 안의 방출 시각을 구하고, 기존 위치·누적 회전 이력으로 당시의 입구 위치와 속도를 계산한다. 새 입자의 첫 적분·경계 이동 검사·압력·속도 복원은 태어난 이후의 시간만 사용한다. 기존 입자는 기존 고정 간격을 유지한다. 버퍼 부족 시 재고를 차감하지 않고 밀린 방출량을 쌓아두지 않는다.
- 출구에 입자가 압축되어 옆으로 튀지 않도록, 초기 상대 속도는 지정한 `exitSpeed`와 기존 Fill의 입자 간격(반경×1.75)을 유지하는 속도 중 큰 값을 사용한다. 최대 속도 설정으로 제한하며 입자량·전역 물리 반경·계산 횟수는 바꾸지 않는다.
- 잔의 열린 벽과 받침, 지거 아래 몸체, 스푼, 셰이커와 얼음통에 별도 물리 형상을 둔다. 도구 외형은 단순화한 충돌 형상이다. 기울어진 얼음통에서는 실제 Rigidbody2D 얼음 프리팹이 나온다.
- `PhysicsLabWorld`가 아이템 등록, 고정 스텝, 충돌 쌍, 스왑과 세션 초기화를 관리한다. `PhysicsLabInteractor`는 집기와 최근 입력 기반 투척을 담당한다. `PhysicsLabBody`는 자세·재고·형상과 방출을 보유한다.
- 집기/우클릭 해제의 0도 복귀는 기존 Interactor와 Body의 공통 자세 변경 경로를 재사용하며, 커서 이동/도착 확인은 기존 `BartendingPointerAnchor`를 호출한다. 기존 BottleController/IceBinController의 전용 복귀 상태나 슬롯 로직은 가져오지 않는다. 포커스가 없거나 다른 바텐딩 뷰포트가 활성화된 경우 커서를 강제로 옮기지 않는다.
- `PhysicsLabGpuLiquid`는 인스턴스별 컴퓨트 셰이더 복사본·버퍼·재료 테이블을 소유한다. `Shaders/PhysicsLabLiquid.compute`는 기존 PBF/XPBD의 독립 복사본이며 기존 셰이더를 변경하지 않는다.
- 액체의 시간 적분은 설정된 고정 서브스텝을 사용한다(기본 2회, 물리 주기 0.02초에서 회당 0.01초). 물체의 이동량·회전량은 이 횟수와 시간 간격을 바꾸지 않는다. 빠른 병·잔·도구·얼음의 이동은 접촉 가능한 입자/경계 쌍에 대한 별도 이동 경로 검사로 처리한다.
- 이동 경로 검사는 시작 위치·끝 위치·누적 회전으로 실제 경로를 평가한다. 회전이 커질 때 늘어나는 것은 그 접촉 쌍의 경로 검사뿐이며, 다른 액체의 압력·점성 계산은 추가 실행하지 않는다. 국소 검사 한도 초과는 GPU 카운터에 기록하고 `ReadSweepExhaustions()`로 검사한다.
- 감쇠·점성·벽 마찰·스플래시 전달 계수는 0.01초 기준에서 실제 시뮬레이션 시간으로 환산한다. 이웃 입자의 속도는 별도 스냅샷에서 읽어 같은 GPU 커널의 읽기/쓰기 순서가 결과에 섞이지 않게 한다.
- 열린 잔의 액체 소유권은 실제 잔 윤곽과 충돌하지 않는 가상 입구 선으로 판정한다. 주둥이를 벗어나면 소유권을 해제한다. 스왑은 양쪽 소유자 ID를 한 커널에서 옮겨 이중 이동을 방지한다.
- 기본 GPU 입자는 0.5ml, 버퍼는 4096개다. 가득 차면 방출을 보류한다. 비동기 readback 이전/이후의 예약 수를 분리해 중복 예약을 막는다. GPU 미지원/초기화 실패는 화면에 오류로 표시하며 성공으로 간주하거나 기존 CPU 풀을 자동 실행하지 않는다.
- 렌더링은 해당 카메라의 URP 렌더링 직전에 GPU 버퍼를 읽어 밀도·색·최대 커버리지를 누적하고 메타볼 표면으로 합성한다. 기존 `GpuLiquidAccumulation`과 `LiquidMetaballComposite` 셰이더를 그대로 재사용하며, `PhysicsLabGpuLiquid.Rendering.cs`가 이 월드의 버퍼·재질·RenderTexture만 관리한다. 기존 메타볼 컴포넌트, GPU 싱글턴과 전역 Render Pipeline 에셋은 변경하지 않는다.
- 공중 입자는 속도 방향으로 길어지고 폭이 줄어 물줄기를 표현한다. 마지막 표시 패스는 표면 가장자리에 얇은 하이라이트를 더한다. 표시 반경·길이·연결 강도는 물리 반경, 입자 위치·속도·소유권과 ml에 영향을 주지 않는다. 액체는 잔/도구의 뒷면 위, 앞면 아래에 그린다.

## 액체 표시 조절

`Data/PhysicsLabLiquidSettings.asset`의 Surface rendering 항목을 사용한다. `containedRenderRadius`는 용기 안 입자의 표시 반경, `airborneRenderRadius`와 `airborneStretch`는 공중 물줄기의 굵기와 길이, `surfaceMergeStrength`는 가까운 입자 사이 연결 강도다. `surfaceHighlightStrength`와 `surfaceHighlightWidth`로 가장자리 빛을 조절한다. `surfaceResolutionScale`은 표면 텍스처 해상도이며, 가장 긴 변은 2048픽셀로 제한한다.

`PhysicsLabGpuLiquid.useSurfaceRendering`을 끄면 같은 GPU 입자를 이전 원형 표시로 비교할 수 있다. 표면 셰이더가 없거나 지원되지 않으면 경고와 `SurfaceRenderingError`를 남기고 원형 표시로 돌아간다. GPU 시뮬레이션 실패와 구분한다. 창/카메라 출력 크기가 바뀌면 텍스처를 재생성하고, 월드를 끄면 렌더링 자원을 해제한다.

이번 단계는 표면 연결·물줄기·하이라이트다. 용기별 마스킹이나 별도 합성은 아직 없으므로, 아주 가까운 용기 사이에 표면이 시각적으로 이어지거나 경계에서 표시 반경만큼 번질 수 있다. 굴절·거품·테이블 웅덩이도 포함하지 않는다.

### 병에서 나오는 연속 물줄기

`PhysicsLabGpuLiquid.Streams.cs`와 전용 누적 셰이더는 같은 병·같은 방출 구간의 연속 입자를 연결한다. 입자 구조체는 그대로 두고 출처, 발행 토큰, 이전 토큰, 방출 시각과 충돌 이력을 별도 GPU 버퍼에 보관한다. 토큰 조회 시 실제 입자의 토큰도 대조하므로 입자 슬롯이 재사용되어도 오래된 줄기가 다시 연결되지 않는다. 렌더링에서 GPU 입자를 CPU로 읽어오지 않는다.

잔의 열린 입구를 통과하면 소유권만 바뀌고 낙하 중인 물줄기 연결은 유지한다. 실제 벽에 닿거나 같은 잔의 고인 액체에 닿은 입자는 연결을 해제하고 기존 메타볼 표면에 합친다. 뒤따르는 줄기는 액체에 합쳐진 마지막 입자까지 연결하여 수면 직전의 틈을 막지만, 벽에 부딪힌 입자까지 연결하지 않는다. 이미 접촉한 입자의 상태는 GPU 서브스텝마다 먼저 복사한 뒤 이웃 검사에 사용하므로 같은 패스에서 접촉 판정이 줄기 전체로 번지지 않는다. 입자 위치·속도·ml와 계산 간격은 이 표시 전환으로 바뀌지 않는다.

물줄기 연결 구간은 잡힌 도구를 포함한 고체도 관통하지 않도록 검사하고, 서로 다른 두 용기 소유의 입자는 연결하지 않는다. 기존 물리의 잡힌 물체 충돌 규칙 자체는 유지한다. 병을 세우거나 순간이동·스왑·초기화하면 입구 연결을 끊고 이미 나온 액체는 독립적으로 떨어진다.

병의 `mouthDirectionLocal`이 0이면 자동 방향을 사용한다. `mouthWidth`는 입구 물줄기 폭이며, `overrideMouthLip`/`mouthLipLocal`로 표시 시작점을 보정할 수 있다. 기존 프리팹은 ItemDef의 입구 좌표와 외부 오프셋에서 입술 위치를 계산하므로 재생성 없이 적용된다. Builder로 새로 생성하면 입술 좌표를 명시적으로 저장한다. 기존 ItemDef와 입구 편집기는 수정하지 않는다.

Settings의 `streamMaximumTimeGap`(기본 0.075초)보다 늦게 나온 방울이나 `streamMaximumLength`(기본 0.65 월드 단위)보다 먼 입자는 연결하지 않는다. `useStreamRendering`을 끄면 추가 GPU 패스를 건너뛰고 이전 메타볼 표시와 비교한다. `useSurfaceRendering`을 끄면 원형 입자를 확인할 수 있다. 동시에 표시할 입구 연결은 월드당 최대 64개다.

## 다른 테스트 씬에서 재사용

샌드박스의 `PhysicsLab` 루트, 카메라와 필요한 프리팹을 함께 복사하면 된다. 직접 구성할 때는 루트에 World/GpuLiquid/Interactor를 두고 독립 Settings, 그리기 Shader, Camera, floorColliders를 연결한다. 프리팹은 World 자식에 두거나 `body.Attach(world)`로 등록한다. 카메라 cullingMask에는 아이템 레이어를 포함한다. 런타임에서 테이블/렌더 카메라와 아이템 레이어를 함께 구성해야 한다.

`Fill(vessel, ingredient, requestedMl)`은 실제 생성한 양을 반환한다. 물리 공간에 들어가는 양은 입자 반경·그림 스케일·잔 형상에 좌우되며 ItemDef의 표기 용량을 자동으로 채우지 않는다. 이 샌드박스의 시드 액체는 유동을 확인하기 위한 샘플이다. 레시피·주문·결제에 연결하려면 이 물리 프리팹을 채택하는 별도 통합이 필요하다.

## 검증

`Slainte > Physics Lab > Validate Play Mode`는 저장된 샌드박스를 열고 실제 Play Mode/GPU에서 검증한다. `PhysicsLabValidator.BuildAndValidate`는 생성과 검증을 함께 수행하므로 새 PhysicsLab 프리팹/씬을 다시 생성한다. 편집한 PhysicsLab 에셋을 보존하려면 재생성 대신 Validate만 사용한다.
