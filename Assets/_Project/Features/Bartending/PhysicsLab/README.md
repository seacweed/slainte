# 슬롯 없는 바텐딩 물리 샌드박스

기존 게임플레이와 분리한 병·잔·도구 프리팹 실험 환경이다. 기존 컨트롤러, 슬롯, 액체 풀, GPU 싱글턴, 제작/영업 시스템과 씬은 수정하지 않는다. 기존 ItemDef, GlassDef, ToolDef와 그림은 읽기 전용 원본으로 사용한다.

## 실행

`Scenes/BartendingPhysicsSandbox.unity`를 열어 Play하거나 `Slainte > Physics Lab > Create or Open Sandbox` 메뉴를 선택한다. 프리팹 24개(병 15, 잔 4, 도구 4, 얼음 1)가 `Prefabs/`에 있다. 씬에는 병 3개, 잔 2개, 도구 4개가 배치된다. Build Settings에 기존 씬을 추가하거나 바꾸지 않는다.

| 조작 | 동작 |
| --- | --- |
| 좌클릭 | 집기 / 내려놓기. 클릭 전 최근 이동 속도로 던지기 |
| 우클릭 + 마우스 상하 이동 | 잡은 물체 회전. 양방향 여러 바퀴 허용 |
| 우클릭 해제 | 위치와 각도 유지. 자동 원위치/세우기 없음 |
| 천천히 다른 물체 위에서 내려놓기 | 두 물체 위치 스왑. 원래 각도와 내용물 소유자 유지 |
| C | 잡은 셰이커의 덮개 열기/닫기 |
| R | 테스트 세션 전체 재시작(재고·생성 얼음·GPU 버퍼 포함) |

개별 물체의 회전 초기화 기능은 없다. R은 검증용 전체 세션 초기화다. 겹침을 해소할 수 없는 위치에서는 내려놓기/스왑을 취소하고 계속 잡고 있는다.

## 동작 및 구조

- 모든 물체와 테이블은 숫자 레이어 29를 사용한다. TagManager나 전역 충돌 행렬을 변경하지 않는다.
- 놓인 물체는 Rigidbody2D Dynamic이며 병, 잔, 도구끼리 부딪혀 밀리고 쓰러진다. 잡은 물체는 Kinematic으로 이동하며 다른 큰 물체/테이블과의 충돌을 일시 무시한다. 얼음은 잡은 잔과도 물리 충돌한다.
- 병의 주둥이 방향과 실제 자세로 쏟기를 판단한다. 손을 놓은 병도 기울어져 있으면 흐른다. GPU가 입자를 수락한 양만 병 재고에서 차감한다. 움직이는 주둥이의 속도를 방출 입자에 전달한다.
- 잔의 열린 벽과 받침, 지거 아래 몸체, 스푼, 셰이커와 얼음통에 별도 물리 형상을 둔다. 도구 외형은 단순화한 충돌 형상이다. 기울어진 얼음통에서는 실제 Rigidbody2D 얼음 프리팹이 나온다.
- `PhysicsLabWorld`가 아이템 등록, 고정 스텝, 충돌 쌍, 스왑과 세션 초기화를 관리한다. `PhysicsLabInteractor`는 집기와 최근 입력 기반 투척을 담당한다. `PhysicsLabBody`는 자세·재고·형상과 방출을 보유한다.
- `PhysicsLabGpuLiquid`는 인스턴스별 컴퓨트 셰이더 복사본·버퍼·재료 테이블을 소유한다. `Shaders/PhysicsLabLiquid.compute`는 기존 PBF/XPBD의 독립 복사본이며 기존 셰이더를 변경하지 않는다.
- 이동/각속도에 따라 경계 보간 서브스텝을 늘린다(2~128). 이는 수치 연산량의 상한이며 조작 각도 제한이 아니다. 병·도구·얼음 경계도 GPU에 올린다.
- 열린 잔의 액체 소유권은 실제 잔 윤곽과 충돌하지 않는 가상 입구 선으로 판정한다. 주둥이를 벗어나면 소유권을 해제한다. 스왑은 양쪽 소유자 ID를 한 커널에서 옮겨 이중 이동을 방지한다.
- 기본 GPU 입자는 0.5ml, 버퍼는 4096개다. 가득 차면 방출을 보류한다. 비동기 readback 이전/이후의 예약 수를 분리해 중복 예약을 막는다. GPU 미지원/초기화 실패는 화면에 오류로 표시하며 성공으로 간주하거나 기존 CPU 풀을 자동 실행하지 않는다.
- 렌더링은 해당 카메라의 URP 렌더링 직전에 GPU 버퍼에서 직접 원형 입자를 그린다. 기존 메타볼 렌더러나 전역 Render Pipeline 에셋을 변경하지 않는다.

## 다른 테스트 씬에서 재사용

샌드박스의 `PhysicsLab` 루트, 카메라와 필요한 프리팹을 함께 복사하면 된다. 직접 구성할 때는 루트에 World/GpuLiquid/Interactor를 두고 독립 Settings, 그리기 Shader, Camera, floorColliders를 연결한다. 프리팹은 World 자식에 두거나 `body.Attach(world)`로 등록한다. 카메라 cullingMask에는 아이템 레이어를 포함한다. 런타임에서 테이블/렌더 카메라와 아이템 레이어를 함께 구성해야 한다.

`Fill(vessel, ingredient, requestedMl)`은 실제 생성한 양을 반환한다. 물리 공간에 들어가는 양은 입자 반경·그림 스케일·잔 형상에 좌우되며 ItemDef의 표기 용량을 자동으로 채우지 않는다. 이 샌드박스의 시드 액체는 유동을 확인하기 위한 샘플이다. 레시피·주문·결제에 연결하려면 이 물리 프리팹을 채택하는 별도 통합이 필요하다.

## 검증

`Slainte > Physics Lab > Validate Play Mode`는 저장된 샌드박스를 열고 실제 Play Mode/GPU에서 검증한다. `PhysicsLabValidator.BuildAndValidate`는 생성과 검증을 함께 수행하므로 새 PhysicsLab 프리팹/씬을 다시 생성한다. 편집한 PhysicsLab 에셋을 보존하려면 재생성 대신 Validate만 사용한다.

2026-09-19 Unity 6000.3.5f2, RTX 3070 / Direct3D11에서 최종 실행 `PhysicsLabEvidence/07-final-isolation-validation`은 종료 코드 0으로 통과했다. 집기, 양방향 다회전, 자세 유지, 투척, 도구 충돌로 병 쓰러짐, 스왑, 셰이커 액체 보존/쏟아짐, 병→잔 전달, 얼음 방출, 초기화, 가라앉은 액체 소유권 및 이동, 예약 용량 제한, 비활성화 후 재활성화를 검사했다. 1024개 실제 GPU 입자 부하에서도 위치/속도의 유한성을 확인했다.

자동 검증은 조작 API와 물리/GPU 실행을 확인한다. 마우스 감도와 플레이 감각은 사람의 플레이테스트가 추가로 필요하다. 보고서의 batch 프레임 간격은 GPU 시간이나 실제 게임 FPS/최적화 성과가 아니다. 이 버전은 원형 입자 표시를 사용하고, 흘린 액체는 월드 경계 밖에서 회수하며 테이블 웅덩이는 만들지 않는다.

Unity 실행은 루트의 `PhysicsLabEvidence/Run-Unity.ps1`로 실행별 폴더에 명령, Editor 로그, stdout/stderr, 종료 코드와 새로운 충돌 덤프를 보존한다. 기존 폴더를 덮어쓰거나 자동 재시도하지 않는다. 초기 샌드박스 캐시 접근 충돌과 중간 검증 실패도 별도로 남아 있다. 기록 요약은 `PhysicsLabEvidence/README.md`를 참조한다.
