# GPU 액체 비교 실험

기존 PhysicsLab을 수정하지 않고 별도 씬에서 물리와 표시 방식의 차이를 비교한다.

## 실행

Unity 메뉴 **Slainte > Fluid GPU Experiment > Open Comparison** 또는
`Scenes/FluidGpuComparison.unity`를 열고 Play를 누른다. Compute Shader를 지원하는 GPU가 필요하다.
기존 게임 씬, Build Settings, Resources 로딩 및 액체 백엔드를 교체하지 않는다.

| 선택 | 액체 물리 | 표시 |
| --- | --- | --- |
| 1 / A Current | 현재 PhysicsLab PBF 복사본 | 현재 표면과 스트림 복사본 |
| 2 / B Physics | 참고 저장소 원리를 적용한 GPU 압력·근접 압력·점성 | A와 같은 표시 |
| 3 / C Surface | B와 동일 | 실제 GPU 입자의 밀도 누적과 등고선 표시 |
| 4 / D Surface (기본·개발 기준) | C와 동일 | 틱 보간·이웃 분포 타원·실제 벽 마스크 |
| 5 / E Liquid | 용량 보정·벽 밀도·반복 밀도 제약·전단 점성·젖음 | D 표면 + 재료별 광학 표현 |

모드를 바꾸면 현재 재생 동작을 처음부터 시작한다. 두 시뮬레이터를 동시에 실행하지 않는다.
A/B/C/D는 같은 입자 반경을 유지한다. E는 ml·간격·반경·커널을 함께 보정하며, 같은 용기와 재생 경로로 비교한다.

- **Manual:** 좌클릭 집기/놓기, 우클릭 회전. 우클릭을 놓으면 각도만 복귀하고 물체는 마우스 이동을 계속 따른다. 자동 복귀 회전은 투척 회전력에 포함하지 않으며 복귀 중 사용자의 이동 속도는 유지한다.
- **놓기·스왑:** 좌클릭하면 잡은 물체를 현재 이동·회전 속도로 놓는다. 클릭한 위치에 겹치는 대상이 있으면 속도에 관계없이 그 물체를 이어서 잡으므로, 움직이며 스왑하면 기존 물체는 던져진다. 새로 잡은 물체에는 이전 물체의 투척 속도를 넘기지 않는다. 어느 물체도 이전 집기 위치로 되돌리지 않으며, 바닥이나 다른 놓인 물체와의 겹침은 놓을 때 보정한다. 자동으로 똑바로 돌아오는 움직임은 투척 속도에 포함하지 않는다.
- **잡기 중 충돌:** 잡은 물체는 테이블·다른 물체·외부 얼음을 통과하지만 자기 용기 안의 얼음과 액체 접촉은 유지한다. 자유 액체는 잡은 잔의 벽에도 부딪힌다. 좌우 벽·천장에서는 잡은 물체의 외곽 이동 범위를 제한한다.
- **액체 다시 받기:** 잡은 잔과 놓인 잔 모두 열린 입구를 바깥에서 안으로 통과한 활성 액체를 받는다. 옆면/바닥 겹침이나 내려놓기만으로 액체를 흡수하지 않는다. 벽·천장에 부딪힌 액체도 다시 받을 수 있으며, 하단 시뮬레이션 범위 밖에서 폐기된 액체는 돌아오지 않는다. 입자 양과 조성을 유지하고 소유권만 바꾼다.
- **얼음:** 잔을 잡기 전 내부 얼음의 소속을 확인하고, 빠른 이동·회전 중에도 벽을 통과하지 않도록 보호한다. 얼음은 동적 Rigidbody로 계속 움직이며 열린 입구로 쏟아질 수 있다. 밖으로 나온 얼음은 액체처럼 테이블을 통과해 아래로 떨어진다. 테이블 아래에서 놓아도 위로 끌어올리지 않는다.
- **얼음 버켓:** 병처럼 외곽 고체와 재고를 가진 공급원이다. 자유 액체를 내부에 담지 않으며 기울이면 재고에서 얼음을 배출한다.
- **쉐이커:** 놓인 쉐이커의 뚜껑과 스트레이너를 각각 클릭해 분리하고 가까이 가져가 놓으면 재부착한다. 스트레이너에 붙은 뚜껑은 함께 이동한다. 뚜껑만 열면 액체는 출구로 흐르고 얼음은 남는다. 스트레이너까지 열면 둘 다 통과한다. 잡은 쉐이커의 C 키는 밀폐 → 뚜껑 제거 → 스트레이너 제거 → 밀폐 순서로 전환한다.
- **Rest:** 같은 잔에 60 ml를 넣고 안정화한다.
- **Pour:** 0.5초부터 4.5초까지 20 ml/s를 요청한 뒤 병을 세운다. E는 잔량·입구·기울기·재질에 따라 실제 유량과 시작/종료 응답이 달라진다. 받는 잔은 놓인 상태로 고정한다.
- **Tilt:** 같은 60 ml 잔을 135도까지 기울인다.
- **Stir:** 움직이지 않는 잔 내부에서 숟가락을 움직인다. 실제 도구 경계를 사용한다.
- **SealedShake:** 60 ml를 요청한 밀폐 셰이커를 움직이고 회전한다. 기준 A/B/C/D는 초기 배치 한도로 56.5 ml가 들어가며 E는 보정한 간격으로 채운다.
- **VolumeCheck:** 잔 종류와 30·60·120 ml를 선택하여 정지한 잔의 양과 높이를 비교한다. A/B/C를 바꿔도 선택한 잔과 요청량을 유지한다. `Requested`는 요청량, `Queued`는 생성 예약량, `Not filled`는 초기 배치 공간 부족으로 넣지 못한 양이다. `In glass`·`Outside`·`Active`는 GPU에서 읽은 현재 액체량이다. `Outside`에는 자유 액체와 다른 용기 소유 액체를 포함한다.
- **R:** 현재 동작을 처음부터 다시 실행한다. Manual을 누르면 원래 배치와 조작으로 복귀한다.

VolumeCheck의 `Particle height (95%)`는 잔 바닥부터 액체량 기준 95% 지점의 입자 중심까지 높이에 입자 반경을 더한 값이다. 실제 렌더링 수면 높이와는 구분한다. `Mean speed`는 잔 내부 소유 입자의 ml 가중 평균 속력이다. 첫 GPU 읽기가 끝나기 전에는 측정 대기 상태를 표시한다. 수면이 안정되었다고 자동 판정하지 않으며, 높이 단위 `u`는 Unity 월드 단위다.

E는 용기 전체 내부 면적을 용량 ml로 나누어 2D 유효 깊이를 정한다. 초기 간격과 밀도 제약, 표시 면적이 이 기준을 공유한다. 입자 자체의 ml는 변하지 않는다. 초기 배치가 요청량보다 적게 끝나면 `Not filled`에 표시하며 숨기지 않는다. 자동 측정과 결과는 `FluidGpuExperimentEvidence`를 참조한다.

## D/E 개선 기능

- **표면:** 전체 물리 틱 사이를 보간한다. 생성·재사용·리셋·스왑에서 이전 위치가 섞이지 않도록 토큰과 이력을 검증한다. 같은 소유권의 이웃 분포로 타원을 만들고, 공유 충돌 윤곽으로 벽과 벽 너머의 표시를 막는다. 열린 입구와 실제 외부 방울은 유지한다.
- **E 물리:** 용기별 ml/면적, 부분 입자 질량, 벽 근처 밀도 보정과 반복 밀도 제약을 사용한다. 전단 점성, 약한 응집, 벽 접선 감쇠와 젖음은 재질 설정에 따른다. 정밀 접촉각이나 완전한 3D 유체를 재현하는 모델은 아니다.
- **재질:** E의 Auto/Water/Spirit/Syrup/Milk 버튼으로 점성·응집·젖음·투명도·거품 수명을 비교한다. Auto는 재료 메타데이터를 사용하며 우유는 명시적으로 선택한다.
- **붓기:** 병 실루엣을 내부 저장 공간의 근사로 사용한다. 잔량과 중력 방향에서 출구 수두를 구하고, 유한한 시작/종료 응답과 마지막 부분 방울을 생성한다. 승인한 ml만 병에서 차감한다.
- **E 얼음과 효과:** 완료된 GPU 상태로 용기 안 얼음에 제한된 부력과 저항을 적용한다. 잡은 용기의 내부 얼음도 포함한다. 잡은 물체의 외부 충돌 무시와 테이블 통과 규칙은 유지한다. 거품·기포는 최대 128개인 표현용 풀이고 ml는 0이다. 소리는 `FluidExperimentEffects.enableAudio`로 켤 수 있으며 기본은 꺼져 있다.
- **회계와 연결:** `Gpu.Ledger`는 요청·예약·생성·활성·폐기·전달량과 재료별 양을 같은 완료 틱으로 제공한다. `IngredientsIn`은 용기별 재료량을 읽는다. `TryTransferContents`는 세대·스냅샷 번호가 일치하는 상태에서만 한 번 전달하고 고유 영수증을 반환한다. 기존 게임에는 자동 연결하지 않는다.

## GPU 구현

원본 [Unity2DFluidSim](https://github.com/Zombie1111/Unity2DFluidSim)의
`73abe0aeae35ba717146e0195f2c2c3b73663e89` 커밋을 참고했다. 원본의 CPU Burst 작업을 그대로 넣은 것이 아니라,
거리 가중치 q²/q³의 밀도·근접 밀도, 합산 압력, 서로 접근하는 입자에만 작용하는 방사 방향 점성을 GPU 커널로 옮겼다.

이웃 읽기와 결과 쓰기를 분리하여 각 스레드는 자신의 결과만 쓴다. 실제 ml에 따른 가중치, 음압 한도,
가속도·변위 한도를 둔 실험 방식이며 원본의 순차 이웃 갱신과 수치적으로 같지 않다.
밀집 상태의 안전 한도 때문에 모든 상황에서 전체 운동량이 정확하게 보존된다고 보장하지 않는다.

중력, 이웃 검색, 압력, 점성, 용기·도구 충돌, 혼합과 입자 색 계산은 Compute Shader에서 실행한다.
물리 적분은 물체 이동량과 무관한 고정 간격을 유지한다. 기본 0.02초당 2개 substep이다.
기존의 ml 회계, 용기 소유권, 연속 충돌, 공간 분할과 바디 경계 조기 배제 구조는 실험 폴더 안에 복사하여 재사용한다.

C의 밀도 표면은 입자를 합산해서 표시한다. 공중·용기 내부를 같은 방식으로 처리하며 속도에 따라 제한된 타원형으로 늘린다.
밀도 임계값과 가장자리 완화를 적용하며 물리 입자의 위치와 부피를 바꾸지 않는다.
병 입구에는 최근 입자와의 짧은 밀도 보정 하나만 허용한다. 기본 거리 한도는 4반경, 생성 후 0.06초다.
이전 토큰을 따라 긴 선으로 입자를 잇는 기존 리본은 C에서 사용하지 않는다.

## 조정 위치

- `Data/FluidExperimentLiquidSettings.asset`: 기준 방식의 반경·압력·점성과 E의 커널·밀도 반복·벽 보정·안정성 한도.
- 씬의 `FluidExperimentGpuLiquid`: C의 support radius, 속도 타원 비율, 임계값, 가장자리 폭, 입구 보정.
- `Runtime/FluidExperimentComparison.cs`: 같은 입력을 재생하는 비교 제어기.
- `Runtime/FluidExperimentMaterials.cs`: 물·술·시럽·우유의 물리 및 표시 프리셋.
- `Shaders/FluidExperimentReference.hlsl`: B/C/D의 기준 GPU 물리.
- `Shaders/FluidExperimentImproved.hlsl`: E의 보정된 GPU 물리.
- `Shaders/FluidExperimentImprovedSurface.compute`, `FluidExperimentImprovedAccumulation.shader`, `FluidExperimentImprovedComposite.shader`: D/E의 보간·타원·벽 가림·합성.

Play 중에는 설정 에셋의 런타임 복사본을 사용한다. GPU 초기화 때 읽는 물리 계수를 바꾼 경우 모드를 다시 선택하여 재초기화한다.
물리 계수와 표시 계수는 실제 비교를 통해 조정할 초기값이다. 이 실험을 기존 게임의 기본 액체로 자동 적용하지 않는다.
쏟아진 액체가 설정의 시뮬레이션 영역을 벗어나면 기존 방식과 동일하게 입자 슬롯을 회수한다.
화면의 ml는 현재 활성 입자의 양이며, 재생 중 처음 넣은 총량과 다를 수 있다.

## 분리 및 검증

스크립트 이름·네임스페이스, Compute Shader, 프리팹, 설정, 충돌 프로파일, 씬 GUID를 분리했다.
그림과 ItemDef, 기존 누적/합성 셰이더는 읽기 전용 참조로 재사용한다. 성능 측정 컴포넌트는 별도 Player에 `-fluid-benchmark`를 명시한 경우에만 생성한다. 일반 실행과 Editor에서는 활성화하지 않는다.
원본과 이 실험을 한 씬에 합치는 사용법은 검증 대상이 아니다.

검증 소스, 실행별 명령·종료 코드, 실패 기록과 측정치는 프로젝트 루트의 `FluidGpuExperimentEvidence`에 있다.
검증용 프로젝트는 별도 폴더에서 생성하며 원본 프로젝트를 Unity로 열어 저장하지 않는다.
기능 검증은 용량·재료별 보존, 표면 보간과 벽 가림, 붓기·젓기, 잡기·스왑·던지기와 일반 Play Mode를 포함한다.
Player 부하 측정은 고정 물리 틱과 프레임당 한 번의 명시적 오프스크린 렌더링을 사용한다. CPU 물리 제출과 카메라 렌더 호출 시간을 구분하며, 실제 게임 FPS나 측정되지 않은 GPU 실행 시간으로 해석하지 않는다.
참고 코드의 MIT 표기와 변형 내역은 `ThirdParty`를 참조한다.
