# GPU 액체 비교 실험

기존 PhysicsLab을 수정하지 않고 별도 씬에서 물리와 표시 방식의 차이를 비교한다.

## 실행

F/G Manual에는 오른쪽 상단의 Ice/Hot 디스펜서가 있다. 비교 UI 없는 재사용 런타임과 `Scenes/FluidRuntimeSample.unity`에서도 같은 디스펜서를 사용한다. 수납 중 위쪽 파란 버튼은 Ice, 아래쪽 빨간 버튼은 Hot을 선택하며 같은 버튼을 다시 누르면 None으로 꺼진다. 버튼 밖 본체를 좌클릭하면 집고 다시 좌클릭하면 호스가 감기며 수납 위치로 복귀한다. 디스펜서에는 전용 조작·충돌 규칙이 적용된다. 들고 있을 때 우클릭은 수직 배출이며 커서를 고정하거나 회전하지 않는다. 본체는 집은 동안에도 바닥·다른 물체와 충돌하는 강체로 목표를 따라가므로 장애물 앞에서는 커서와 떨어져 멈출 수 있다. 아래의 일반 도구 우클릭 회전·집기 중 충돌 무시 규칙은 디스펜서에 적용하지 않는다.

복귀 중에는 모드 변경과 재집기를 막는다. 첫 장애물의 경계 상자 모서리를 후보로 우회하고, 유효한 경로가 없으면 대기한다. 복귀 시간 0.5초는 속도를 정하는 목표값이며 거리·가감속·장애물에 따라 실제 수납 시간은 길어질 수 있다. 호스는 길이 변화와 처짐을 표시하며 충돌하지 않는다.

수납 위치와 호스 고정점은 각 World의 좌표계를 기준으로 생성한다. 좁은 런타임 환경에서는 본체 수납 위치를 좌우 벽·천장 안으로 보정하고, 호스 고정점도 함께 옮겨 경계 안에 둔다. 잔량·모드 표시는 해당 World의 입력 카메라를 우선 사용하고, 없으면 액체 출력 카메라와 `Camera.main` 순서로 선택한다. 따라서 런타임에 연결한 카메라는 MainCamera 태그 없이도 디스펜서 상태를 표시할 수 있다.

두 모드는 5000 ml를 공유한다. 물은 40 ml/s, 얼음은 0.3초마다 하나이며 얼음 1개는 10 ml를 차감한다. 양수인 10 ml 미만 잔량도 마지막 얼음 하나를 허용하고 0으로 만든다. 생성 거절·노즐 차단·동시 입자/경계 한도에서는 잔량을 보존하고 대기량을 누적하지 않는다. 5000 ml는 총 재고이며 얼음 500개의 동시 유지를 보장하지 않는다. 생성된 얼음은 다시 집을 수 없고 GPU 시뮬레이션 범위를 1u 이상 벗어나면 정리된다. Hot은 기존 물 성분을 80°C 온도 데이터로 생성하며 열교환·증발·얼음 녹음은 구현하지 않는다. 용량·유량·간격·복귀 목표 시간·온도는 `Prefabs/Dispenser.prefab`과 `Data/DispenserHotWater.asset`에서 조절한다. 소진 후 자동 충전은 없으며 R·모드 재초기화는 None/5000 ml/원래 수납 위치로 복구한다. A–E와 자동 비교 시나리오에는 디스펜서가 나타나지 않는다.


F/G의 허리케인 잔은 놓거나 던진 상태에서 강하게 충돌하면 제공된 16개 파편으로 깨진다. 액체·얼음·가니쉬는 현재 위치와 속도를 유지한 채 잔 소속을 벗어난다. 파편은 테이블·벽에 부딪혀 남으며 다시 집을 수 없다. R 또는 모드 재시작은 파편을 정리하고 원래 잔을 복원한다. 다른 잔과 A–E는 기존 동작을 유지한다.

**7번 키 또는 `7: G Explosive Breakage` 버튼**으로 폭발 비산 모드를 선택한다. G는 F의 액체 물리·표시·조작·파손 기준을 그대로 사용하며, 파손 순간에만 파편에 바깥쪽 속도·월드 위쪽 속도·교대 방향 회전을 추가한다. 액체·얼음·가니쉬에는 폭발력을 주지 않는다. Manual에서 허리케인 잔을 높이 놓거나 강하게 던져 파손을 확인하고, `R`로 다시 시험한다. `6`으로 F에 돌아가면 기존의 작은 분리 움직임으로 비교할 수 있다. 아래에서 F라고 설명한 액체·입력 동작은 G에도 적용된다.

F에서는 쓰러진 잔을 집어 수직으로 세우는 순간에만 잔 안 액체를 함께 옮긴다. 자동 회전으로 입자가 가속되지 않으며 기존 속도 크기와 액체량은 유지한다. 집은 뒤 직접 움직이거나 기울일 때, 우클릭을 놓아 회전이 복귀할 때는 기존 액체 물리가 동작한다.

Unity 메뉴 **Slainte > Fluid GPU Experiment > Open Comparison** 또는
`Scenes/FluidGpuComparison.unity`를 열고 Play를 누른다. Compute Shader를 지원하는 GPU가 필요하다.
기존 게임 씬, Build Settings, Resources 로딩 및 액체 백엔드를 교체하지 않는다.

| 선택 | 액체 물리 | 표시 |
| --- | --- | --- |
| 1 / A Current | 현재 PhysicsLab PBF 복사본 | 현재 표면과 스트림 복사본 |
| 2 / B Physics | 참고 저장소 원리를 적용한 GPU 압력·근접 압력·점성 | A와 같은 표시 |
| 3 / C Surface | B와 동일 | 실제 GPU 입자의 밀도 누적과 등고선 표시 |
| 4 / D Surface | C와 동일 | 틱 보간·이웃 분포 타원·실제 벽 마스크 |
| 5 / E Liquid | 용량 보정·벽 밀도·반복 밀도 제약·전단 점성·젖음 | D 표면 + 재료별 광학 표현 |
| 6 / F Cohesive Liquid (기본·개발 기준) | D 입자 크기를 유지한 반복 압축 보정·독립 응집·재료별 전단 점성·보존형 혼합 | D와 동일 |
| 7 / G Explosive Breakage | F와 동일 | F와 동일 + 파손 시 파편 폭발 비산 |

모드를 바꾸면 현재 재생 동작을 처음부터 시작한다. 두 시뮬레이터를 동시에 실행하지 않는다.
A/B/C/D/F/G는 같은 입자 반경을 유지한다. E는 ml·간격·반경·커널을 함께 보정하며, 같은 용기와 재생 경로로 비교한다. 시작 모드와 개발·검증 기준은 F다. 4번 키로 D를 비교하고 6번 키로 F로 돌아간다.

F는 현재 기본 물리 모드이며 D는 비교용으로 유지한다. 입자당 ml·반경·초기 채움·병 배출·표면 표시를 D와 동일하게 두고, 압축된 입자만 밀어내는 반복 밀도 보정과 독립적인 근거리 응집을 적용한다. F의 Water/Spirit/Syrup/Milk 버튼은 액체 입자의 점성과 응집 계수만 바꾸며, E의 병 유량·젖음·광학·거품·부력 기능을 켜지 않는다. 우선 Rest/Pour/Stir/SealedShake를 같은 조건으로 비교한 후 Manual에서 조작한다.

F/G 공통 액체 설정은 `Liquid Settings`의 `Coherent liquid (F/G; keeps the D particle and volume scale)` 그룹에 있다. 기본 압축 보정은 4회이며 `cohesiveDensityIterations=0`으로 끌 수 있다. `cohesiveSurfaceTension=0`과 `cohesiveShearViscosity=0`은 각각 응집·전단 점성을 끈다. 밀도 보정은 중력이나 물체 이동을 다시 적분하지 않는다. 응집은 물방울 표현을 위한 유한 거리 근사이며 정확한 접촉각 모델은 아니다. 선택적 벽 밀도 근사는 기본 0이고 E의 용량 보정을 이식하지 않는다. 총 ml와 성분별 ml를 보존하는 혼합을 사용한다.

- **Manual:** 좌클릭 집기/놓기, 우클릭 회전. 우클릭 회전 중 시스템 커서는 잠그고 숨기며, 물체의 회전 중심에 화면 커서를 표시한다. 회전량은 마우스의 상대 이동량으로 계산하므로 작은 움직임도 연속적으로 반영한다. 우클릭을 놓으면 즉시 잠금이 풀리고, 각도가 복귀하는 동안에도 물체는 마우스 이동을 계속 따른다. 시스템 커서 위치가 반영되는 동안에도 화면 커서와 물체는 이동하며, 좌표 전환 자체는 물체를 움직이거나 투척 속도를 만들지 않는다. Esc·포커스 이탈·초기화·비활성화는 잠금을 해제한다. 자동 복귀 회전은 투척 회전력에 포함하지 않으며 복귀 중 사용자의 이동 속도는 유지한다.
- **놓기·스왑:** 좌클릭하면 잡은 물체를 현재 이동·회전 속도로 놓는다. 클릭한 위치에 겹치는 대상이 있으면 속도에 관계없이 그 물체를 이어서 잡으므로, 움직이며 스왑하면 기존 물체는 던져진다. 새로 잡은 물체에는 이전 물체의 투척 속도를 넘기지 않는다. 어느 물체도 이전 집기 위치로 되돌리지 않으며, 바닥이나 다른 놓인 물체와의 겹침은 놓을 때 보정한다. 자동으로 똑바로 돌아오는 움직임은 투척 속도에 포함하지 않는다.
- **잡기 중 충돌:** 잡은 물체는 테이블·다른 물체·외부 얼음을 통과하지만 자기 용기 안의 얼음과 액체 접촉은 유지한다. F 가니쉬는 집은 동안 물리 반응과 벽에 의한 이동·회전 제한을 모두 끈다. 잔·얼음·천장·좌우 벽과 겹쳐도 커서를 그대로 따른다. 놓을 때 충돌을 복원한다. 자유 액체는 잡은 잔의 벽에도 부딪힌다. 다른 도구는 기존 좌우 벽·천장의 이동 범위 제한을 유지한다.
- **액체 다시 받기:** 잡은 잔과 놓인 잔 모두 열린 입구를 바깥에서 안으로 통과한 활성 액체를 받는다. 옆면/바닥 겹침이나 내려놓기만으로 액체를 흡수하지 않는다. 벽·천장에 부딪힌 액체도 다시 받을 수 있으며, 하단 시뮬레이션 범위 밖에서 폐기된 액체는 돌아오지 않는다. 입자 양과 조성을 유지하고 소유권만 바꾼다.
- **얼음:** 잔을 잡기 전 내부 얼음의 소속을 확인하고, 빠른 이동·회전 중에도 벽을 통과하지 않도록 보호한다. 평소 쌓임은 실제 다각형의 Physics2D 접촉에 맡기고, 빠른 벽 통과나 깊은 침투만 얼음 형상을 사용한 연속 검사로 복구한다. 정지한 잡힌 용기의 자세를 반복 설정하거나 얼음을 강제로 재우지 않는다. 이 CPU 처리는 모든 비교 모드가 공유한다. 얼음은 동적 Rigidbody로 계속 움직이며 열린 입구로 쏟아질 수 있다. 밖으로 나온 얼음은 액체처럼 테이블을 통과해 아래로 떨어진다. 테이블 아래에서 놓아도 위로 끌어올리지 않는다.
- **얼음 버켓:** 병처럼 외곽 고체와 재고를 가진 공급원이다. 자유 액체를 내부에 담지 않으며 기울이면 재고에서 얼음을 배출한다. 전면의 잔량 표시가 실제 재고에 따라 7단계로 바뀌며, 초기화하면 가득 찬 표시로 복원된다.
- **가니쉬:** Manual 화면 오른쪽 위의 노란 통(Synth Lemon Peel)과 주황 통(Nananga Peel)을 클릭하면 해당 가니쉬 한 개를 집는다. 통은 고정된 무제한 공급원이다. 커서로 옮긴 뒤 다시 클릭하면 놓이며, 한 번 놓거나 던진 조각은 다시 집을 수 없다. 통에서는 계속 새 조각을 꺼낼 수 있다. 가니쉬를 놓는 클릭은 잔이나 통을 자동으로 집지 않는다. F에서는 놓은 뒤 동적 Rigidbody2D가 중력·관성·충돌·자유 회전을 처리하고, 액체 흐름과 부력은 힘으로 적용한다. 잔의 이동·회전을 강제로 따라가지 않으며 열린 입구로 나올 수 있다. A–E는 기존 동작을 유지한다. R/모드 재시작은 생성된 조각과 집기 상태를 초기화한다.
- **얼음·가니쉬 재집기:** 한 번 놓인 개체는 클릭 대상에서 제외되며, 그 아래 잔은 계속 집을 수 있다. 버킷에서 배출한 얼음도 이미 놓인 상태로 처리한다. 이 집기 규칙은 모든 모드에 공통으로 적용한다.
- **F 가니쉬 표시:** 가니쉬는 액체 표시 마스크와 GPU 액체 충돌 경계에서 제외한다. 잔 안에서는 액체(0) 위, 잔 앞면(4) 뒤인 순서 2로 표시하며 통에서 꺼낸 외부 조각은 기존 순서 45를 유지한다. 얼음·잔의 표시 마스크와 A–E 비교 모드는 유지한다.
- **병의 회전 복귀:** 자동 회전과 그에 따른 벽·천장 위치 보정은 배출 입자를 가속하지 않는다. 사용자가 직접 움직이거나 회전한 속도는 전달하며, 배출 위치·방향·유량은 실제 병 자세를 따른다.
- **쉐이커:** 놓인 쉐이커의 뚜껑과 스트레이너를 각각 클릭해 분리하고 가까이 가져가 놓으면 재부착한다. 스트레이너에 붙은 뚜껑은 함께 이동한다. 뚜껑만 열면 액체는 출구로 흐르고 얼음은 남는다. 스트레이너까지 열면 둘 다 통과한다. 잡은 쉐이커의 C 키는 밀폐 → 뚜껑 제거 → 스트레이너 제거 → 밀폐 순서로 전환한다.
- **Rest:** 같은 잔에 60 ml를 넣고 안정화한다.
- **Pour:** 0.5초부터 4.5초까지 20 ml/s를 요청한 뒤 병을 세운다. E는 잔량·입구·기울기·재질에 따라 실제 유량과 시작/종료 응답이 달라진다. 받는 잔은 놓인 상태로 고정한다.
- **Tilt:** 같은 60 ml 잔을 135도까지 기울인다.
- **Stir:** 움직이지 않는 잔 내부에서 숟가락을 움직인다. 실제 도구 경계를 사용한다.
- **SealedShake:** 60 ml를 요청한 밀폐 셰이커를 움직이고 회전한다. 기준 A/B/C/D/F는 초기 배치 한도로 56.5 ml가 들어가며 E는 보정한 간격으로 채운다.
- **VolumeCheck:** 잔 종류와 30·60·120 ml를 선택하여 정지한 잔의 양과 높이를 비교한다. A/B/C를 바꿔도 선택한 잔과 요청량을 유지한다. `Requested`는 요청량, `Queued`는 생성 예약량, `Not filled`는 초기 배치 공간 부족으로 넣지 못한 양이다. `In glass`·`Outside`·`Active`는 GPU에서 읽은 현재 액체량이다. `Outside`에는 자유 액체와 다른 용기 소유 액체를 포함한다.
- **R:** 현재 동작을 처음부터 다시 실행한다. Manual을 누르면 원래 배치와 조작으로 복귀한다.

VolumeCheck의 `Particle height (95%)`는 잔 바닥부터 액체량 기준 95% 지점의 입자 중심까지 높이에 입자 반경을 더한 값이다. 실제 렌더링 수면 높이와는 구분한다. `Mean speed`는 잔 내부 소유 입자의 ml 가중 평균 속력이다. 첫 GPU 읽기가 끝나기 전에는 측정 대기 상태를 표시한다. 수면이 안정되었다고 자동 판정하지 않으며, 높이 단위 `u`는 Unity 월드 단위다.

E는 용기 전체 내부 면적을 용량 ml로 나누어 2D 유효 깊이를 정한다. 초기 간격과 밀도 제약, 표시 면적이 이 기준을 공유한다. 입자 자체의 ml는 변하지 않는다. 초기 배치가 요청량보다 적게 끝나면 `Not filled`에 표시하며 숨기지 않는다. 자동 측정과 결과는 `FluidGpuExperimentEvidence`를 참조한다.

F의 얼음 주변 액체 접촉은 겹침 복구와 실제 운동에 의한 속도 응답을 분리하고, 여러 접촉면의 조건을 함께 푼다. 얼음의 침투 복구 이동이 액체를 가속하지 않도록 구분하면서 실제 이동·회전은 충돌에 반영한다. 액체의 반경·ml·재질 계수·렌더링은 유지한다. 얼음은 액체에 영향을 주는 단방향 구조를 유지하며 액체에서 얼음으로의 부력·반작용은 추가하지 않는다. 가니쉬의 별도 정책은 아래와 같다. 실행별 검증 결과와 제한은 증거 문서에 기록한다.

F 가니쉬는 GPU 액체 경계에서 제외되어 액체를 직접 밀거나 가속하지 않는다. 집고 있을 때는 고체 콜라이더를 트리거로 전환하고, 커서 이동·회전·자동 복귀 중에 겹침을 보정하지 않는다. 클릭으로 놓을 때만 주변의 가까운 빈 위치를 찾아 깊은 겹침을 정리한 뒤 고체 콜라이더와 자유 회전하는 동적 Rigidbody2D를 복원한다. 놓인 후의 위치·각도 적분과 잔·얼음의 일반 접촉은 Unity 물리가 처리한다. 잔을 이동·회전하거나 놓는 동작으로 내부 가니쉬의 자세나 속도를 직접 덮어쓰지 않는다. 급격한 잔 이동의 벽 횡단은 기존 윤곽 기반 연속 검사로 복구하고, 실제 콜라이더에서 소스 픽셀 한 개보다 깊은 침투만 위치 보정한다. 이 복구는 각도·각속도를 바꾸지 않는다. 네이티브 접촉의 한 픽셀 이내 오차는 허용한다.

완료된 GPU 읽기(통상 5 Hz)의 월드 유속·잠김으로 `AddForce`와 `AddTorque`를 적용한다. 긴 축 양쪽의 유속 차이와 잠김 차이가 회전과 자세 복원에 기여한다. 가니쉬가 잔에 부착되지 않으므로 유속에서 잔의 속도를 빼지 않는다. 0.35초보다 오래된 스냅샷과 이전 리셋 세대는 무시하며 물리 루프에 GPU 동기 읽기를 추가하지 않는다. 이는 제한된 부력·흐름 힘이며 양방향 유체 결합은 아니다. 이전 `garnishLiquidMotionTransfer` 필드는 과거 에셋 호환용으로 남아 있고 현재 F에는 적용되지 않는다. 동적 강체 전환 전 스냅샷은 `Library/GarnishDynamicOriginal`에 보존했다.

## D/E 개선 기능

- **표면:** 전체 물리 틱 사이를 보간한다. 생성·재사용·리셋·스왑에서 이전 위치가 섞이지 않도록 토큰과 이력을 검증한다. 같은 소유권의 이웃 분포로 타원을 만들고, 공유 충돌 윤곽으로 벽과 벽 너머의 표시를 막는다. 열린 입구와 실제 외부 방울은 유지한다.
- **E 물리:** 용기별 ml/면적, 부분 입자 질량, 벽 근처 밀도 보정과 반복 밀도 제약을 사용한다. 전단 점성, 약한 응집, 벽 접선 감쇠와 젖음은 재질 설정에 따른다. 정밀 접촉각이나 완전한 3D 유체를 재현하는 모델은 아니다.
- **재질:** E의 Auto/Water/Spirit/Syrup/Milk 버튼으로 점성·응집·젖음·투명도·거품 수명을 비교한다. Auto는 재료 메타데이터를 사용하며 우유는 명시적으로 선택한다.
- **붓기:** 병 실루엣을 내부 저장 공간의 근사로 사용한다. 잔량과 중력 방향에서 출구 수두를 구하고, 유한한 시작/종료 응답과 마지막 부분 방울을 생성한다. 승인한 ml만 병에서 차감한다.
- **E 얼음과 효과:** 완료된 GPU 상태로 용기 안 얼음에 제한된 부력과 저항을 적용한다. 잡은 용기의 내부 얼음도 포함한다. 잡은 물체의 외부 충돌 무시와 테이블 통과 규칙은 유지한다. 거품·기포는 최대 128개인 표현용 풀이고 ml는 0이다. 소리는 `FluidExperimentEffects.enableAudio`로 켤 수 있으며 기본은 꺼져 있다.
- **회계와 연결:** `Gpu.Ledger`는 요청·예약·생성·활성·폐기·전달량과 재료별 양을 같은 완료 틱으로 제공한다. `IngredientsIn`은 용기별 재료량을 읽는다. `TryTransferContents`는 세대·스냅샷 번호가 일치하는 상태에서만 한 번 전달하고 고유 영수증을 반환한다. 기존 게임에는 자동 연결하지 않는다.

## GPU 구현

원본 [Unity2DFluidSim](https://github.com/Zombie1111/Unity2DFluidSim)의
`73abe0aeae35ba717146e0195f2c2c3b73663e89` 커밋을 참고했다. 원본의 CPU Burst 작업을 그대로 넣은 것이 아니라,
거리 가중치 q²/q³의 밀도·근접 밀도, 합산 압력, 서로 접근하는 입자에만 작용하는 방사 방향 점성을 GPU 커널로 옮겼다.

이웃 읽기와 결과 쓰기를 분리하여 각 스레드는 자신의 결과만 쓴다. 실제 ml에 따른 가중치, 음압 한도,
가속도·변위 한도를 둔 실험 방식이며 원본의 순차 이웃 갱신과 수치적으로 같지 않다.
밀집 상태의 안전 한도 때문에 모든 상황에서 전체 운동량이 정확하게 보존된다고 보장하지 않는다.

중력, 이웃 검색, 압력, 점성, 용기·도구 충돌, 혼합과 입자 색 계산은 Compute Shader에서 실행한다.
물리 적분은 물체 이동량과 무관한 고정 간격을 유지한다. 기본 0.02초당 2개 substep이다.
기존의 ml 회계, 용기 소유권, 연속 충돌, 공간 분할과 바디 경계 조기 배제 구조는 실험 폴더 안에 복사하여 재사용한다.

C의 밀도 표면은 입자를 합산해서 표시한다. 공중·용기 내부를 같은 방식으로 처리하며 속도에 따라 제한된 타원형으로 늘린다.
밀도 임계값과 가장자리 완화를 적용하며 물리 입자의 위치와 부피를 바꾸지 않는다.
병 입구에는 최근 입자와의 짧은 밀도 보정 하나만 허용한다. 기본 거리 한도는 4반경, 생성 후 0.06초다.
이전 토큰을 따라 긴 선으로 입자를 잇는 기존 리본은 C에서 사용하지 않는다.

## 조정 위치

- `Data/HurricaneBreakage.asset`: `Slainte > Fluid GPU Experiment > Select Hurricane Breakage Settings` 메뉴로 선택한다. Inspector 맨 위의 `Minimum Impact Speed`(기본 6, 월드 단위/초)와 `Minimum Impulse Per Mass`(기본 4, 충격량/잔 질량)를 올릴수록 덜 깨진다. 두 조건을 모두 충족해야 깨지므로 먼저 속도 기준을 올리고, 빠르지만 약한 충돌도 버티게 하려면 충격량 기준을 올린다. 기존 기본값은 3.5/2였다. F/G 모드의 허리케인 잔에 적용되며 손에 들린 상태·자동 자세 보정은 제외한다. `Shard Motion`의 분산 속도·감쇠·재질은 파손 후 파편 움직임만 바꾼다. `Explosive Breakage (G mode only)`의 `Explosion Speed`(5)는 바깥쪽 비산 속도, `Explosion Upward Speed`(2.5)는 위로 튀는 속도, `Explosion Angular Speed`(240도/초)는 추가 회전 속도다. 세 값을 모두 0으로 두면 G에서도 F와 같은 파편 움직임을 사용한다. 파편의 이미지·윤곽·중심·면적은 `Build Hurricane Breakage` 메뉴로 다시 작성할 수 있으며 조절한 임계값은 유지된다.
- `Data/FluidExperimentLiquidSettings.asset`: 기준 방식의 반경·압력·점성과 E의 커널·밀도 반복·벽 보정·안정성 한도.
- 씬의 `FluidExperimentGpuLiquid`: C의 support radius, 속도 타원 비율, 임계값, 가장자리 폭, 입구 보정.
- `Runtime/FluidExperimentComparison.cs`: 같은 입력을 재생하는 비교 제어기.
- `Runtime/FluidExperimentMaterials.cs`: 물·술·시럽·우유의 물리 및 표시 프리셋.
- `Shaders/FluidExperimentReference.hlsl`: B/C/D의 기준 GPU 물리.
- `Shaders/FluidExperimentImproved.hlsl`: E의 보정된 GPU 물리.
- `Shaders/FluidExperimentImprovedSurface.compute`, `FluidExperimentImprovedAccumulation.shader`, `FluidExperimentImprovedComposite.shader`: D/E의 보간·타원·벽 가림·합성.

Play 중에는 액체 설정 에셋의 런타임 복사본을 사용한다. GPU 초기화 때 읽는 물리 계수를 바꾼 경우 모드를 다시 선택하여 재초기화한다. 파손 프로파일은 공유 에셋을 직접 참조하므로 Inspector 변경이 다음 충돌부터 적용되고 Play 종료 후에도 유지된다. 이미 깨진 잔은 `R`로 복구한 뒤 다시 시험한다.
물리 계수와 표시 계수는 실제 비교를 통해 조정할 초기값이다. 이 실험을 기존 게임의 기본 액체로 자동 적용하지 않는다.
쏟아진 액체가 설정의 시뮬레이션 영역을 벗어나면 기존 방식과 동일하게 입자 슬롯을 회수한다.
화면의 ml는 현재 활성 입자의 양이며, 재생 중 처음 넣은 총량과 다를 수 있다.

## 재사용 런타임과 기획자 도구

`Slainte > Fluid GPU Experiment > Designer`에서 프리팹을 검색하고 작업본의 수치·충돌 형상을 편집한다. 작업본은 원본 프리팹 및 충돌·파손·스플래시 프로파일과 분리되어 있다. **Save**로 반영하고 **Revert**로 저장 상태를 다시 연다. 공유 프로파일은 사용 중인 프리팹 수를 확인하고, 해당 객체만 다르게 만들려면 **Clone for this prefab**을 선택한다. 편집 중 Undo/Redo를 사용할 수 있다. 생성된 파편 형상은 `HurricaneShardGeometry.asset`, 기획자가 조절하는 강도·비산·감쇠는 `HurricaneBreakage.asset`에 따로 저장한다.

**Create variant**는 현재 저장된 프리팹을 부모로 하는 실제 Prefab Variant를 만든다. 변형을 저장해도 부모 연결은 유지되며, 개별 프로파일 복제를 기본 선택한다. `Assets` 아래 다른 기능 폴더에 저장한 변형도 카탈로그에 등록되어 다음 실행의 검색 목록에 나타난다. 먼저 작업본을 Save하면 그 변경을 바탕으로 변형을 만들 수 있다. Undo/Redo는 장면 편집과 같은 Unity 실행 이력을 사용한다. Save는 저장 경계이며, 저장된 작업본의 편집 이력은 정리한다.

도구의 낙하 시험은 높이·초기 속도·액체량·Natural/Explosive·반복 횟수를 지정하여 실제 Play Mode에서 실행한다. 시험에는 작업본의 스냅샷과 별도 씬을 사용하며, 종료하면 이전 에디터 씬으로 돌아간다. 시험 결과에는 파손 여부, 충격 속도/충격량, 파편 수·속도, 액체량과 보존 오차가 표시된다. 시험 중 Inspector에서 원본 에셋을 직접 수정하는 대신 작업본을 수정한 뒤 새 시험을 시작한다.

일반 Play 및 스크립트 리로드에서도 미저장 작업본과 프로파일 복제 선택을 복원한다. 임시 시험·복구 스냅샷은 `DesignerTemp`에 만들고 정상 복구 후 제거하며 Git에서 제외한다. 저장하지 않은 기존 씬은 시험을 위해 저장하거나 덮어쓰지 않는다.

- `Open Runtime Sample`: 비교 UI 없는 조립 예제 `Scenes/FluidRuntimeSample.unity`를 연다. 채워진 잔과 병·쉐이커·숟가락을 배치했으며, Play 시 World가 연결된 디스펜서를 생성한다.
- `Assemble New Runtime Scene`: 새 씬에 런타임·환경·카메라·허리케인 잔을 연결한다. 이후 Designer에서 다른 프리팹을 배치할 수 있다.
- `Build Reusable Runtime Assets`: 누락된 공통 프리팹과 카탈로그를 생성하고, 기존 런타임의 디스펜서 참조가 비어 있으면 보충한다. 이미 연결된 디스펜서 프리팹과 조정값, 기존 설정·템플릿·샘플 씬은 유지한다.
- `Prefabs/Runtime/FluidExperimentRuntime.prefab`: World, GPU 액체, 입력, 효과, RuntimeRig를 가진 실행 모듈이다. 카메라·환경은 `RuntimeRig`의 명시적 참조로 연결하고, 디스펜서는 World의 `dispenserPrefab`으로 연결한다. `FluidExperimentComparison`은 포함하지 않는다.
- `Prefabs/Runtime/FluidExperimentEnvironment.prefab`: 테이블·좌우 벽·천장과 환경 바인딩이다. `Table Holds Liquid`를 끄면 테이블에서 액체만 배수한다. 켜면 유한 폭의 테이블 위 액체가 충돌하며 가장자리 밖으로 흐른 액체는 하단 월드 경계에서 회수된다.
- `Prefabs/Runtime/GlassShard.prefab`, `ShakerPart.prefab`: 파편·분리형 쉐이커 부품의 공통 템플릿이다. 생성 시 비활성 상태에서 소유자·형상·물리 값을 설정한 뒤 활성화한다.
- `Data/ShakerParts.asset`: 쉐이커 뚜껑·스트레이너 영역, 액체 통로, 두께·질량·부착 거리를 편집한다. 쉐이커 프리팹은 각 그림을 직접 참조하며, 기존 이름·픽셀 좌표 탐색은 이전 에셋의 호환 경로로만 남긴다.
- `Data/FluidExperimentCatalog.asset`: 기존 객체 프리팹과 기존 `ItemDef`를 참조한다. 별도의 재료 데이터베이스를 만들지 않는다. 런타임 객체 추가는 `RuntimeRig.Spawn`/`SpawnObject`, 액체량 연동은 기존 `Liquid.Ledger`, `IngredientsIn`, `TryTransferContents`를 사용한다.

디스펜서는 World당 하나를 생성·관리하는 고정 도구여서 공용 Catalog와 Designer의 일반 객체 목록에서 제외한다. `RuntimeRig.Spawn`/`SpawnObject`로 추가하지 않고 World의 `dispenserPrefab`을 지정한다. 디스펜서 수치와 스프라이트는 해당 프리팹 Inspector에서 조절한다. 비교 씬의 R·모드 재초기화와 런타임의 `RuntimeRig.ResetRig()`는 관리 중인 디스펜서의 모드·재고·수납 상태를 초기화한다.

새 런타임의 **Natural**은 충격 기반 액체 스플래시·유리 조각 충돌을 사용하고, **Explosive**는 여기에 기존 G 파편 비산을 더한다. 원래 비교 씬의 F/G는 이전 검증 조건을 유지한다. 개별 잔의 `splashProfile`이 비어 있으면 런타임의 `defaultSplashProfile`을 사용한다. 효과를 끄려면 해당 잔의 스플래시 프로파일에서 `Strength`를 0으로 설정한다.

`DefaultBreakageSplash.asset`의 Strength, Maximum Delta Speed, Radial/Tangent/Lift Weight, Impact Radius/Falloff, Explosive Multiplier로 액체의 튀는 정도를 조정한다. 기존 낙하 속도를 유지하고 충격 속도와 질량당 충격량에 따른 제한된 추가 속도만 한 번 전달한다. 바닥 충격은 위·양옆, 벽 충격은 벽에서 멀어지는 방향으로 튄다. 활성 입자와 아직 태어나지 않은 GPU/CPU 예약 입자 모두 같은 계산을 사용하며 ml·성분·생성 시점을 유지한다.

조각의 GPU 충돌은 **원래 얇은 유리 벽과 해당 조각 실루엣의 교집합**이다. 정면 그림 전체를 고체로 채우지 않으므로 액체가 있던 빈 공간이 갑자기 막히지 않는다. 조각 이동·회전은 연속 충돌과 움직이는 고체 접촉에 반영한다. 조각이 액체를 미는 단방향 결합이며, 액체가 파편을 다시 밀어내는 양방향 강체 결합이나 3D 유체 모델은 아니다. `maximumShardLiquidSegments` 기본 512를 초과하면 해당 조각의 액체 충돌을 생략하고 `SkippedShardBoundaryCount`로 보고한다. 일반 잔·도구의 경계 예산을 먼저 확보한다.

## 분리 및 검증

스크립트 이름·네임스페이스, Compute Shader, 프리팹, 설정, 충돌 프로파일, 씬 GUID를 분리했다.
그림과 ItemDef, 기존 누적/합성 셰이더는 읽기 전용 참조로 재사용한다. 성능 측정 컴포넌트는 별도 Player에 `-fluid-benchmark`를 명시한 경우에만 생성한다. 일반 실행과 Editor에서는 활성화하지 않는다.
새 런타임은 다른 씬에서 명시적 참조로 조립할 수 있다. 기존 영업 씬의 레거시 액체·슬롯 컨트롤러를 자동 교체하지는 않는다.

검증 소스, 실행별 명령·종료 코드, 실패 기록과 측정치는 프로젝트 루트의 `FluidGpuExperimentEvidence`에 있다.
검증용 프로젝트는 별도 폴더에서 생성하며 원본 프로젝트를 Unity로 열어 저장하지 않는다.
기능 검증은 용량·재료별 보존, 표면 보간과 벽 가림, 붓기·젓기, 잡기·스왑·던지기와 일반 Play Mode를 포함한다.
Player 부하 측정은 고정 물리 틱과 프레임당 한 번의 명시적 오프스크린 렌더링을 사용한다. CPU 물리 제출과 카메라 렌더 호출 시간을 구분하며, 실제 게임 FPS나 측정되지 않은 GPU 실행 시간으로 해석하지 않는다.
참고 코드의 MIT 표기와 변형 내역은 `ThirdParty`를 참조한다.
