# GPU 액체 실험 개발 방향

작성일: 2026-09-30  
기준 구현: `8ad64e8` — 독립 GPU 액체 A/B/C 비교 실험  
문서 상태: 개발 방향과 검증 계획 정리. 아래 발전 항목은 후속 구현 대상이다.

## 1. 목표와 유지할 원칙

현재 C 버전을 기반으로, 양이 정확하고 조작에 반응하며 하나의 연속된 액체로 보이는 시스템을 만든다. 현재 2D 스프라이트 그림체를 유지하면서 병의 붓기, 잔의 수면, 도구 접촉, 혼합, 쏟아짐을 발전시킨다.

- 기존 PhysicsLab, 게임 씬, 레거시 액체 시스템과 사용자의 미커밋 변경을 보존한다.
- 현재 A/B/C는 비교 기준으로 유지하고 발전안은 실험 폴더 안의 추가 모드와 설정으로 분리한다.
- GPU 물리와 GPU 표면 렌더링을 유지한다. 기존 공간 격자, 충돌 프로파일, 생성 시각, ml 데이터, 연속 충돌, 입력 모듈은 최대한 재사용한다.
- 물리 적분 간격은 고정한다. 잡은 물체의 이동량에 따라 전체 액체의 시간 간격이나 substep 수를 변경하지 않는다.
- 물리 결과와 표시 결과를 분리한다. 표시 개선이 입자의 위치, 재료량, 게임 판정을 바꾸지 않도록 한다.
- Unity 실패나 충돌은 실패로 기록한다. 실행 명령, 개별 로그, 종료 코드와 충돌 덤프를 보존하고 원인을 분석한 뒤 변경된 조건으로 검증한다.

## 2. 현재 기반과 검증의 범위

| 모드 | 물리 | 표시 |
| --- | --- | --- |
| A | 기존 PhysicsLab PBF 복사본 | 기존 표면과 스트림 |
| B | 참고 저장소의 압력·근접 압력·점성 원리를 적용한 GPU 방식 | A와 같은 표시 |
| C | B와 동일 | 실제 GPU 입자의 밀도 누적과 임계값 표면 |

현재 구현은 기본 붓기, ml 회계, 용기 소유권, 충돌, 혼합, 표면 렌더링과 비교 재생을 제공한다. 참고한 Unity2DFluidSim의 CPU 작업을 그대로 재현한 것은 아니며, GPU 병렬 계산과 기존 프로젝트의 단위·경계 조건에 맞춘 실험 방식이다.

기존 검증 기록은 GPU 검사 277개와 일반 Play Mode 검사 80개, 총 357개 통과다. 이는 해당 검사 범위의 통과이며 아래 항목까지 검증되었다는 뜻은 아니다.

- 같은 ml가 차지하는 화면 면적과 수면 높이의 일관성.
- 혼합 전후의 재료별 ml 보존과 장시간 슬롯 재사용을 포함한 영구 회계.
- 실제로 잡은 숟가락과 액체의 접촉. 자동 Stir는 잔과 숟가락을 unheld kinematic으로 설정한다.
- 다량의 액체가 있을 때의 원거리 독립성. 최종 원거리 회귀 검사는 단일 입자 조건이다.
- 밀집한 잔, 여러 재료, 여러 병의 동시 붓기, 렌더링까지 포함한 최악 부하.
- 수면의 자연스러움, 물줄기 끊김, 시간적 깜빡임에 대한 영상 평가.

기존 약 3.1ms 측정은 분산된 자유 입자 1,000개의 CPU 제출과 GPU 완료 동기화 시간이며 렌더링을 제외한다. 순수 GPU 시간이나 실제 게임 FPS 개선 근거로 사용하지 않는다. 상세 조건은 프로젝트 루트의 `FluidGpuExperimentEvidence/README.md`를 참조한다.

## 3. 양·부피·재료별 회계

현재 ml는 입자에 저장되지만 입자 반경, 평형 간격, 기준 밀도와 표시 면적을 연결하는 기준은 부족하다. 장부상 60ml 보존과 화면에서 같은 부피로 보이는 것은 별개의 문제다.

개발 방향:

- 2D 면적을 ml로 환산하는 규칙과 유효 깊이를 정의한다. 용기 용량·형상·월드 스케일과 모순되지 않는 기준을 먼저 정한다.
- 입자당 ml, 물리 반경, 초기 간격, 커널 반경, 기준 밀도를 함께 보정한다.
- 같은 잔의 30·60·120ml와 여러 잔의 같은 충전 비율에서 평형 수면 높이와 면적을 비교한다.
- 마지막 부분 입자의 질량과 표시 기여량도 실제 ml에 맞춘다.
- 재료별 양을 `Σ(입자 ml × 해당 재료 비율)`로 GPU에서 집계한다.
- 혼합은 양쪽 입자의 유효 시간과 교환량을 일치시키는 보존적인 방식으로 발전시킨다. 입자별 조성 합이 1이라는 검사만으로 재료별 총량 보존을 판단하지 않는다.
- 생성 승인량, 대기 생성량, 활성량, 누적 폐기량, 게임으로 전달한 양을 구분한다. 회수량은 재사용되는 입자 슬롯과 별개의 누적 버퍼에 저장한다.
- 잔량 차감과 실제 생성 승인을 일치시키고, 늦게 도착한 GPU 읽기 결과는 틱·세대 번호로 구분한다.

현재 혼합은 자신의 `stepDt`로 교환량을 계산하고 이후 조성을 정규화한다. 출생 시점이 다른 입자의 비대칭 교환과 고밀도에서의 재료량 변화 가능성을 별도 실험으로 확인해야 한다.

완료 기준은 전체 ml와 재료별 ml를 각각 추적하면서, 반복 붓기 → 혼합 → 쏟기 → 회수 → 슬롯 재사용 후에도 누락이나 중복이 없는 것이다.

## 4. 실제 집기와 액체 충돌

잡기 상태와 유체 충돌 허용 여부를 분리한다. 현재의 held 정책은 물체 중첩과 내부 액체 격리에 유용하지만, 실제 잡은 도구로 젓는 상황에는 추가 정책이 필요하다.

- 잡은 숟가락이 잔 내부 액체를 밀 수 있도록 한다.
- 잡은 잔은 자기 액체와 상호작용하면서 실제로 접촉하는 도구·얼음의 영향을 받도록 한다.
- 용기 소유권에 따른 양 집계와 물리 접촉 허용 조건을 구분한다.
- 서로 다른 잔의 액체가 벽 너머로 힘을 주거나 혼합되지 않도록 한다. 소유권 필터를 단순히 제거해서 해결하지 않는다.
- 테이블과 화면 경계도 GPU 경계 입력으로 연결해 쏟은 액체가 바닥에 모이거나 흘러내리는 동작을 확장한다.
- 얼음 부력과 액체가 도구·물체에 주는 반작용은 후속 단계에서 몸체별 힘·토크 집계와 제한된 비동기 전달로 검토한다.

물리 경계와 표시용 벽 마스크는 `FluidExperimentCollisionProfile`의 같은 윤곽을 재사용한다. 새 콜라이더와 마스크를 각각 수작업으로 작성하지 않는다.

검증은 자동 재생 외에 실제 입력 경로의 집기, 젓기, 이동, 회전, 스왑, 던지기, 해제를 포함한다.

## 5. 병에서 나오는 흐름

현재 유량은 주로 기울기로 결정되며, 잔량은 소진 여부에 사용된다. 입자 간격을 확보하기 위해 방출 속도를 높이는 보정도 있어, 입자 해상도를 바꾸면 흐름의 속도가 달라질 수 있다.

| 항목 | 발전 방향 | 목표 동작 |
| --- | --- | --- |
| 잔량 | 잔량·기울기에서 내부 수면과 출구 상태 계산 | 가득 찬 병과 거의 빈 병의 시작 각도·유량 차이 |
| 입구 | 입구 폭에 따른 방출 위치 분포와 유량·속도·줄기 폭의 일관성 | 입자가 한 줄에 과밀하게 생성되는 현상 완화 |
| 시작 | 입구까지 액체가 도달하는 짧은 응답 시간 | 기울이는 순간부터 자연스럽게 시작되는 흐름 |
| 종료 | 연속 흐름에서 가는 줄기와 방울로 전환 | 병을 세운 뒤 마지막 방울이 떨어짐 |
| 낙하 | 중력에 따른 속도와 단면 변화 반영 | 내려갈수록 빨라지고 가늘어지는 줄기 |
| 병 종류 | 목과 입구 형상별 프로파일 | 좁은 병, 넓은 병, 시럽 용기의 차이 |

병 내부는 우선 잔량과 내부 수면을 계산하는 간단한 저장 액체 모델로 구현한다. 내부 전체 입자 시뮬레이션의 필요성은 이 모델의 결과를 보고 판단한다.

이미 있는 방출 경로 세분화, 정확한 birth time, 병의 선속도·각속도 반영, 출구 clearance, 거절된 생성에 대한 재고 미차감은 유지한다. 유량은 ml 기준이며 입자 개수와 독립적으로 정의한다.

검증에는 잔량·각도별 ml/s, 시작 지연, 종료 후 잔류 방출량, 물줄기 폭, 끊김 구간, 잔에 도달한 ml 비율을 포함한다.

## 6. 압력·점성·표면장력과 벽 접촉

현재 근접 압력은 밀집 반발 항이다. 독립된 표면장력이나 유리벽의 젖음·접촉각 모델과 구분하여 조정한다.

권장 순서:

1. **벽 근처 밀도 보정:** 액체 이웃이 없는 고체 방향의 영향을 기존 윤곽으로 보정한다. 열린 입구의 가상 소유권 선분은 물리 벽에 포함하지 않는다.
2. **압력 안정성:** 밀도 오차, 정지 수면 속도, 충격 후 압축과 회복을 계측한다. 가속도·변위·속도 제한이 상시 작동하는 설정은 개선 대상으로 기록한다.
3. **전단 점성:** 접근 방향 감쇠에 더해 접선 방향 상대 운동의 저항을 다룬다. 젓기와 시럽의 흐름 차이를 표현한다.
4. **표면장력:** 가는 줄기의 목 형성, 방울 분리·합체를 조절한다. 과한 응집으로 구슬이나 젤처럼 뭉치지 않는지 확인한다.
5. **젖음과 접촉각:** 유리벽을 따라 흐르는 액체, 벽에 붙는 방울, 수면 가장자리 곡률을 표현한다.
6. **이동·밀폐 용기:** 입자 위치에서 평가한 용기의 강체 속도와 접촉 마찰을 사용하고 내부 점성과 구분한다. 기존 관통 방지와 안정화 장치는 비교 검증 없이 제거하지 않는다.

밀집 상황에서 현재 명시적 압력 방식의 한계가 지속되면 추가 물리 모드에 반복적인 밀도 보정이나 밀도·발산 제약 solver를 검토한다. 이 선택은 오차와 실제 GPU 비용을 측정한 뒤 결정하며, 전역 적분 간격은 고정한다.

## 7. GPU 표면 복원과 시간 일관성

현재 C는 속도에 따라 표시 타원을 늘린다. 발전안에서는 주변 입자의 배치로 수면 방향과 물줄기 형태를 복원한다.

### 7.1 표시 위치 보간

- 전체 물리 틱의 이전·현재 위치를 별도 GPU 상태로 저장하고 Rigidbody의 표시 시간과 맞춘다.
- 현재 `previousPosition`은 substep 계산용이므로 그대로 화면 보간에 사용하지 않는다.
- 생성 시각, 슬롯 재사용, 리셋, 순간이동에서 오래된 표시 이력이 섞이지 않도록 한다.
- 30·60·120·144fps에서 같은 물리 입력을 재생하고 잔과 액체의 상대 위치를 비교한다.

### 7.2 이웃 분포에 따른 표면 복원

- 마지막 GPU 공간 격자를 재사용해 이웃 평균과 2×2 공분산으로 표시 타원의 방향과 폭을 구한다.
- 고인 액체의 수면은 평평하게, 줄기는 흐름을 따라 이어지게 표현하는 것을 목표로 한다.
- 이웃이 적은 방울은 원형 또는 제한된 속도 늘임을 사용한다.
- 최대 늘임, 최소 두께, 표시 면적을 제한하고 벽 너머나 다른 액체 영역을 무작정 연결하지 않는다.
- 필요하면 타원 변화부터 안정화하고, 영상에서 문제가 확인될 때 제한된 표면 시간 이력을 추가한다.

### 7.3 공유 윤곽에서 생성한 벽 마스크

- 기존 `solids`, `lid`, `interior`에서 실험용 GPU 마스크 또는 로컬 거리장을 생성한다.
- 실제 고체 영역의 표시 침범을 막되 입구와 외부로 쏟아지는 액체는 유지한다.
- 얇은 벽, 서로 맞닿은 두 잔, 뚜껑의 열림·닫힘을 구분한다.
- 거리장 해상도 때문에 얇은 벽이 사라지지 않는지 검증하고 기존 연속 충돌 경로를 유지한다.

### 7.4 평활화와 광학 표현

- 같은 액체 영역 안에서 경계를 보존하는 약한 평활화를 적용한다.
- 가는 줄기와 작은 방울을 지우는 강한 전 화면 블러는 기본 방식으로 사용하지 않는다.
- 두께에 따른 흡수색, 재료별 투명도, 광택 폭을 추가한다. 논리적 혼합색과 보정된 표시 두께를 구분한다.
- 배경 굴절은 별도 배경 캡처와 투명 정렬을 검증할 수 있는 실험 전용 경로에서 후순위로 다룬다.

비교 모드는 다음처럼 확장한다.

| 모드 | 목적 |
| --- | --- |
| A/B/C | 현재 기준 유지 |
| D | 현재 C 물리 + 새 표면으로 표시 개선만 비교 |
| E | 개선 물리 + D와 같은 표면으로 물리 개선 비교 |

동일 GPU 상태 또는 동일 초기 상태와 입력을 사용한다. GPU 슬롯 번호 대신 생성 토큰과 세대 정보를 입자 식별에 사용한다.

## 8. 재료별 표현과 주변 반응

기반이 안정된 뒤 다음 항목을 확장한다.

- 물, 술, 시럽, 우유의 점성·표면장력·투명도·거품 유지 시간 프리셋.
- 젓는 흐름을 따라 색과 조성이 퍼지는 혼합 표현.
- 충돌 강도, 수면 접근, 젓기와 재료 특성에 반응하는 기포·거품.
- 따라낸 뒤 벽면에 남는 얇은 액체와 천천히 내려오는 방울.
- 얼음 부력, 액체 저항, 자유 물체에 대한 반작용.
- 유량과 충돌 강도에 연동되는 붓기·방울·출렁임 소리.

표현용 기포·거품과 실제 ml를 가진 액체를 분리한다. 게임상 손실이나 이동량에 포함되는 방울·벽면 잔류액은 반드시 실제 회계에 포함한다.

## 9. 성능과 게임 연결

성능 계측은 첫 단계부터 진행한다. 정상 Player에서 CPU 작업, Compute GPU, 표면 GPU, 전체 프레임의 평균과 p95/p99를 구분한다. 해상도, 입자 수, 용기 충전율, 셀당 이웃 수와 재료 종류를 함께 기록한다.

측정 결과에 따라 적용할 후보:

| 후보 | 방법과 주의점 |
| --- | --- |
| 활성 입자만 처리 | 활성 인덱스 목록과 간접 dispatch/draw. 처음에는 원본 슬롯을 이동하지 않아 토큰·조성 관계를 유지 |
| GPU 집계 | 용기별 개수·총 ml·재료별 ml·누적 회수량을 작은 결과로 비동기 전달. 전체 입자 읽기는 진단용으로 유지 |
| 이웃 검색 재사용 | 재료마다 같은 검색을 반복하는 혼합 경로 개선 |
| 정렬된 셀 목록 | 밀집 셀의 불규칙한 접근을 줄일 후보. 정렬 자체의 비용까지 측정 |
| 정적 경계 캐시 | 움직이지 않는 경계의 재계산·업로드 감소 |
| 표시 영역과 해상도 | 액체가 있는 영역과 표면 해상도를 중심으로 비용 조정. 물리량·입자 회계를 바꾸지 않음 |

현재 사용하지 않는 표면 RenderTexture의 필요성을 정리하고 모드 전환·재시작·해상도 변경 시 GPU 버퍼, 텍스처와 머티리얼의 해제를 확인한다.

게임 연결은 실험 전용 어댑터부터 준비한다. 생성 요청·승인, 용기 상태, 재료별 양, 폐기와 전달 완료를 명시한다. 주문 제출 같은 확정 동작은 같은 틱의 일관된 상태를 사용한다. 기존 게임 백엔드 교체는 이 문서의 초기 구현 범위에 포함하지 않는다.

## 10. 단계별 구현 범위

| 단계 | 핵심 작업 | 단계 종료 시 확인할 것 |
| --- | --- | --- |
| 준비 | A/B/C 기준 보존, 측정 지표와 동일 입력·영상 비교 도구 | 결과를 재현하고 물리·표시·성능 원인을 분리할 수 있음 |
| 1차 | 양·재료량·충돌 기준, 표시 보간, 이웃 표면, 벽 마스크 | 실제 도구 접촉, 같은 양의 일관된 수면, D 표면 비교 |
| 2차 | 잔량 기반 붓기, 벽 밀도, 압력 안정성, 전단 점성, 표면장력·젖음 | 붓기의 시작·연속 흐름·마지막 방울, E 물리 비교 |
| 3차 | 재료별 표현, 기포·거품·벽면 잔류·얼음 반응, 측정 기반 최적화 | 장시간 안정성, 실제 프레임 예산, 재료량 보존 |
| 연결 준비 | 실험 전용 게임 어댑터와 판정 시점 관리 | 기존 게임 변경 없이 연동 계약을 검증할 수 있음 |

한 번에 한 변화 묶음을 비교한다. 같은 양의 기준을 먼저 정하고, 고정된 물리 상태에서 표시 개선을 병행할 수 있다. 고급 압력 solver, 배경 굴절, 강한 양방향 강체 연동은 효과와 비용을 확인한 뒤 채택한다.

## 11. 검증 기준

아래는 추가할 검증 항목이며 이미 통과한 결과가 아니다. 시각적 허용 오차와 성능 예산은 기준 영상·측정 결과를 확보한 뒤 구현 전에 수치로 확정한다.

| 영역 | 확인 항목 |
| --- | --- |
| 양과 부피 | 30·60·120ml의 수면 높이·면적, 부분 입자, 전체 및 재료별 ml |
| 장기 회계 | 연속 붓기·쏟기·회수·재사용, 생성 실패, 지연된 읽기, 반복 리셋 |
| 자연스러움 | 정지 수면 흔들림, 안정화 시간, 충격 후 압축과 회복, 운동 에너지 변화 |
| 물리 안정성 | NaN/Inf, 압력·속도·변위 제한 발생률, 과도한 팽창·튐 |
| 붓기 | 잔량·각도별 ml/s, 줄기 폭과 끊김, 도달량, 마지막 방울 |
| 충돌 | 얇은 벽, 입구, 고속 이동·회전, 실제 집은 숟가락, 얼음, 테이블 |
| 격리 | 같은 GPU 초기 상태에서 원거리 물체 이동 전후의 다량 입자 비교 |
| 표시 | 수면 봉우리·구멍, 벽 침범 픽셀, 외부 방울 보존, 프레임 간 깜빡임 |
| 프레임률 | 30/60/120/144fps 표시에서 물리 결과와 용기 상대 위치 |
| 부하 | 100/300/600/1,000개와 최대 용량, 밀집 잔, 동시 붓기, 재료 1/4/8/16종 |
| 수명 관리 | 모드 전환·재시작·해상도 변경 반복 후 GPU 메모리 고점과 해제 |

GPU 원자적 생성과 이웃 순서의 차이를 실제 물리 간섭으로 오인하지 않도록 입자 식별과 초기 상태 복원을 명확히 한다. 수치 검사와 동일 입력 영상 비교를 함께 사용하며, 정지 캡처만으로 시간적 떨림이나 끊김을 판단하지 않는다.
