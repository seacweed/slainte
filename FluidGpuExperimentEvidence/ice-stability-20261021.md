# 얼음 충돌·다수 적재 안정화 — 2026-10-21

이 문서는 이전 소스의 검사 기록이다. 이후 수정과 현재 결과는 [최신 동작 보고서](ice-behavior-20261021.md)를 참조한다. 아래 수치를 현재 소스의 검증으로 사용하지 않는다.

F/G의 `NonColliding`과 `Colliding`을 유지하며 기본값은 `NonColliding`이다. 두 모드 모두 얼음은 독립적인 동적 강체로 부력과 상대 유속 저항을 받는다. 가니쉬 표시 보간 수정과 일반 클릭 놓기의 액체 속도·두 위치 이력 보존도 유지한다. 변경은 실험 기능과 해당 검사 도구에 한정한다.

## 원인과 수정

- **다수 얼음 떨림:** 네이티브 다각형 접촉 해석 뒤 가니쉬용 위치 복구가 다시 얼음을 밀었다. 얼음에는 이 사후 복구를 적용하지 않고 기존 네이티브 접촉·고속 용기 벽 횡단 복구를 사용한다. 강제 수면, 운동학적 전환, 위치 고정으로 숨기지 않는다.
- **과한 액체 분출:** 위치 복구 이동을 강체의 실제 속도로 취급하거나 불가능한 좁은 틈의 압축 보정이 운동 속도로 증폭됐다. 실제 강체의 선속도·각속도를 응답에 사용하고 전체 이동 경로는 연속 충돌에 유지한다. 닫힌 얼음 내부 입자는 가까운 외면으로 복구한다. 얼음 접촉은 비탄성 응답을 사용한다.
- **접촉 틈의 증폭:** 들어오는 액체의 공통 유속을 기준으로 새 상대 속도를 제한하고 미해상 압축 잡음을 감쇠한다. 실제 유입 운동과 접촉원 속도를 고려한 속도 예산을 적용한다. 중력 일은 접촉 복구로 수정된 `PreviousPosition`이 아니라 별도 보존한 실제 틱 시작 위치로 계산한다. 정지 얼음이 액체를 계속 가속하지 않도록 한다.
- **잔 벽 누출:** 좁은 틈에서 얼음과 잔 벽 조건을 모두 완화하던 동작을 바꿨다. 잔 벽을 우선하고 얼음 겹침을 완화한다. 투영 후 실제 용기 윤곽도 확인하며, 움직이는 실제 입구를 통과한 정상 배출은 허용한다. 이 복구는 속도 재구성에 추가 충격을 주지 않는다.
- **자기 부력·회전 피드백:** 얼음의 접촉막·최고 방울을 주변 물의 대표 흐름으로 재사용하지 않는다. 얼음 접촉층 밖의 벌크 유속과 수위 분포를 사용하며 액체량·용기 단면·얼음 점유 영역으로 부력용 수위 상한을 제한한다. 얼음 자체 소용돌이를 회전 구동원으로 삼지 않고 네이티브 접촉 회전과 유체 각저항을 유지한다.

`iceContactRelaxationRate` 기본값은 16/s이며 F/G 충돌 얼음의 상대 압축 잡음에만 적용된다. 액체 공통 병진 속도를 전역으로 감쇠하거나 낮은 고정 최대 속도로 교체하지 않는다.

## 실패 기록과 판정 범위

초기·중간 실패 실행은 삭제하지 않았다. `20261021-crowded-ice-before`는 다수 얼음 떨림과 과한 분출을 재현한 기준이다. 복구·벌크 유속·속도 예산만 적용한 중간 후보들은 잔 벽 누출 또는 잔여 압축 운동 때문에 실패했다. 해당 CSV·로그·실제 종료 코드를 그대로 보존한다.

초기 저낙하 세팅은 떠 있는 기존 얼음과 겹치게 새 얼음을 만들 수 있었다. 실제 디스펜서가 겹침 생성을 거절하는 조건에 맞춰 최종 세팅은 생성 전 네이티브 형상 간격을 확인한다. 따라서 저낙하 수치는 초기 세팅과 직접 같은 조건의 개선율로 계산하지 않는다. 반면 8·12개 상단 투입 세팅은 같은 조건으로 비교한다.

최종 수위보다 최고점이 0.5u 이상 높다는 초기 판정은 배수·고체 점유·접촉막으로 달라지는 서로 다른 수위를 비교했다. 이를 저낙하 실제 상향 속도 3u/s 미만, 입구 아래 최고점, 잔 내부 60ml 유지로 바꿨다. 전체 보존량만으로 벽 누출을 통과시키지 않는다.

`20261021-ice-delivered-garnish-motion`, `-garnish-recheck-a`는 혼합물의 12초 정지 판정에서 실패했다. 별도 `20261021-mixed-float-long-observation`의 32초 추적에서는 Synth Lemon과 얼음이 28–32초에도 2초간 최대 0.029615u·8.027도 천천히 구르지만, 고주파 위치 진동은 약 0.000013u 이하인 것으로 구분됐다. 마른 접촉 스택과 부유하는 혼합물에 같은 사실상 고정 조건을 적용하던 검사를 수정했다. **런타임 강제 정지나 추가 감쇠로 이 실패를 숨기지 않았다.** 마른 혼합물은 기존 12초·위치 0.01u·회전 2도 기준을 유지한다. 젖은 혼합물은 24초 관찰 후 마지막 2초의 위치 0.1u·회전 20도 범위, 95백분위 속도 0.15u/s·20도/s, 고주파 진동 0.0015u 및 벽 침투·소속·액체량을 함께 검사한다. 별도 32초 장기 검사에서도 느린 구름과 빠른 떨림을 구분한다. 이는 부유 혼합물이 12초 내 완전히 멈춘다는 보장이 아니다.

포함 HLSL만 바꾼 중간 실행은 Unity 캐시 때문에 수정 프로그램의 실행 증거로 사용하지 않는다. 최종 런처는 주 Compute Shader를 강제 재임포트하고 실행한다. 추가 이력 버퍼를 처음 넣은 `20261021-ice-final-crowded-01`은 D3D11의 8개 UAV 한도를 초과해 커널이 건너뛰어졌고 실패했다. 읽기 전용 바인딩을 분리했으며 최종 감사는 `Skipping dispatch`와 셰이더 오류도 거부한다. 최종 성공 실행만 `ice-stability-audit.json`의 통과 수에 포함한다.

## 검증 한계와 재실행

실제 Unity 6000.3.5f2의 숨긴 D3D11 실행과 네이티브 Physics2D/GPU 결과다. 사람의 시각적 자연스러움 승인, 다른 GPU·플랫폼, 성능 프로파일 결과는 아니다. 기존처럼 얼음 부력·유속 저항과 액체 충돌을 결합하는 근사 모델이며 완전한 질량·운동량 보존 양방향 유체 해석은 아니다. 부력 수위 상한은 입자 반경으로 확장한 얼음 경계 상자를 사용하고, 미해상 좁은 틈에서는 얼음 겹침을 허용한다.

검사 프로젝트를 실행 중인 Editor가 없을 때 저장소 루트에서 실행한다. 새 `Prefix`를 사용해야 기존 증거를 덮어쓰지 않는다.

```powershell
python FluidGpuExperimentEvidence/HarnessSource/prepare_experiment.py --target Library/FluidModelDHarness
powershell -NoProfile -ExecutionPolicy Bypass -File FluidGpuExperimentEvidence/Run-IceStabilityRegressions.ps1 -Prefix NEW_UNIQUE_PREFIX
```

저장된 최종 실행의 감사는 다음 명령으로 다시 확인할 수 있다.

```powershell
$iceAuditRuns = Get-Content FluidGpuExperimentEvidence/ice-stability-final-runs.json -Raw | ConvertFrom-Json
python FluidGpuExperimentEvidence/HarnessSource/audit_ice_stability.py @iceAuditRuns
```
