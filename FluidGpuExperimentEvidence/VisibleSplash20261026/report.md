액체 스플래시의 보이는 비산 보정 — 2026-10-26

앞서 제공한 영상은 액체 속도 변화가 있었지만 화면에서는 주로 흘러내리는 모습이었다. 이전 완료 판단은 시각적 비산을 충분히 입증하지 못했다. 이번에는 실제 렌더 프레임에서 위로 솟고 여러 방향으로 퍼지는 움직임과 OFF/ON 차이를 확인하는 기준을 추가했다.

원인은 두 가지였다. 기존 강도 0.4와 추가 속도 상한 3u/s로는 낙하 관성을 이기기 어려웠다. 또한 빈 잔의 기하학적 중심과 좌우 부호만 사용해 액체 대부분에 비슷한 방향을 주었고, 강도만 높이면 큰 덩어리로 이동했다.

비교 씬 전용 설정을 다음처럼 바꿨다.

| 항목 | 이전 | 현재 |
|---|---:|---:|
| Strength | 0.4 | 2 |
| 추가 속도 상한 | 3u/s | 12u/s |
| 충돌 법선 방향 가중치 | 0.7 | 1.5 |
| 접선 방향 가중치 | 1 | 2 |

| 거리 감쇠 지수 | 1 | 0.5 |
| 퍼짐 중심 | 빈 잔의 중심 | 완료된 액체 스냅샷의 부피 중심 |
| 접선 방향 | 두 방향으로 분할 | 0.8u에 걸쳐 연속적으로 변화 |

현재 액체 중심은 기존의 완료된 GPU 스냅샷을 재사용한다. 스냅샷 당시 잔의 위치·회전에서 현재 자세로 중심을 보정한다. 유효한 스냅샷이 없거나 오래됐거나 초기화됐으면 기존 기하학적 중심으로 복구한다. 파손 처리에 GPU 동기 읽기를 새로 추가하지 않았다. CPU 생성 대기 입자와 GPU 입자는 같은 연속 팬 계산을 사용한다.

기존 입자의 속도에 추가 속도를 한 번 더하는 구조는 유지한다. 전체 액체 속도를 덮어쓰거나 12u/s로 제한하지 않는다. F/G의 액체 설정은 같고 G 파편의 고정 폭발 속도는 액체에 더하지 않는다. 파손하지 않은 낮은 낙하에는 추가 효과가 없다. 기존 재사용 런타임 프로파일에서 새 중심·팬 옵션은 기본 꺼짐이다.

분리된 Unity 6000.3.5f2 / D3D11의 최종 실제 실행 2회에서 376개 항목을 통과했다. 둘 다 실제 종료 코드 0, 시간 초과 없음, 결과 PASS다.

40ml 낙하 파손 시험에서 평균 추가 y 속도는 +9.968u/s였고, 파손 직후 실제 y 속도가 +0.5u/s보다 큰 액체가 40ml였다. 추가 속도의 최대 크기는 부동소수점 오차 범위에서 12u/s를 지켰다. 단순히 추가 속도가 양수인지 확인하던 이전 검사와 달리 실제 최종 속도가 위를 향하는 액체량을 검사한다.

병 충돌 OFF/ON 재현에서는 병 앞쪽 경계보다 0.15u 이상 떨어진 액체의 최대량이 F/G 모두 OFF 32ml, ON 40ml였다. OFF에서도 기존 병-액체 충돌로 비산이 있으므로 OFF를 완전 정지 상태로 해석하지 않는다. ON은 실제 액체 중심을 기준으로 서로 다른 방향의 속도를 받아 병 앞쪽으로 더 퍼진다.

`f-off-on.gif`, `g-off-on.gif`는 왼쪽 OFF, 오른쪽 ON의 실제 카메라 프레임을 같은 배율로 배치한 비교다. `floor.gif`는 낙하 파손 후 상향·좌우 비산, `bottle-f.gif`는 F 병 충돌 영상이다. 모두 파손 후 실제 0.04초 간격의 20프레임이며 합성 입자나 생성한 중간 프레임은 없다. 원본 프레임 목록과 해시는 `motion-previews.json`에 있다. 최종 낙하·병 충돌 PNG도 직접 확인했다. 직접 플레이 체감과는 구분한다.

비교 씬의 기존 액체 통과 바닥 설정은 유지한다. 따라서 올라간 액체가 다시 내려온 뒤 바닥에 고이는 동작은 이번 보정에 포함하지 않는다.
