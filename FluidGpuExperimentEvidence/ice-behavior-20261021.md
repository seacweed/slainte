# 얼음 동작 재분석 및 수정 — 2026-10-21

**수정 및 자동 재현 검사 완료. 필수 16개 검사와 액체 단독 대조 1개 실행이 모두 정상 종료했다.** 이전 정지 수치만으로 자연스러운 움직임까지 해결됐다고 판단할 수 없었다. 두 얼음 모드와 기본 비충돌 선택, 액체를 놓을 때의 속도·위치 이력 보존은 유지한다.

## 확인한 원인과 변경

- 잔 전체의 높은 입자와 평균 속도를 가까운 얼음의 잠김·유속으로 사용했다. 먼 다른 액체 덩어리가 힘을 주지 않도록 가까운 물을 기준으로 샘플링한다.
- 충돌 막과 움직이는 제외 영역을 수위로 재사용해 얼음이 자기 부력 기준을 바꿀 수 있었다. 충돌 모드는 액체량과 실제 고체 다각형에 따른 수위 근사를 사용한다. 평온한 비충돌 수면을 참조하며, 얼음을 먼저 넣었을 때에는 응집 시작 거리 대신 밀도 커널에 따른 면적 추정값을 사용한다.
- AABB 잠김을 실제 얼음 다각형의 잠긴 면적·부력 중심으로 바꿨다. 가니쉬의 긴 축 복원 토크는 재사용하지 않는다.
- 잡힌 용기의 순간 위치 변경과 벽 복구가 네이티브 접촉을 중복 처리했다. 용기는 고정 틱의 네이티브 이동으로 처리하고 완료된 실제 형상의 벽 이탈만 복구한다. 쌓인 얼음의 네이티브 접촉을 별도 보정으로 다시 밀어내지 않는다.
- 빠른 진입의 2g 저항 상한과 심부의 큰 선형 저항이 깊은 침강·긴 상승을 만들었다. 고속 진입 저항, 심부 상승 저항, 수면 감쇠를 구분했다. 마른 얼음에는 0인 힘·토크를 반복 호출하지 않는다.
- 실제 자동 업데이트에서 비충돌 얼음이 국소 압력 응답을 유속으로 받아 튀는 경우가 추가 재현됐다. 두 모드 모두 연결된 액체 덩어리의 실제 이동으로 주변 유속을 추정하는 변경을 적용하고 실제 자동 업데이트에서 재검증했다. 액체의 기존 속도 버퍼는 바꾸지 않는다.

## 검사와 판정

독립 Unity 사본, Unity 6000.3.5f2 / Direct3D11에서 실제 GPU 액체와 Physics2D를 사용한다. 수동 고정 틱과 실제 자동 업데이트·비동기 읽기를 별도 검사한다. 원본 프로젝트를 Unity로 열어 저장하지 않는다.

새 이동 재현은 80ml, 얼음 1/8개, 두 모드의 낙하·이동·회전을 검사한다. 위치 범위 0.02u, 회전 속도 p95 2°/s의 기준은 유지하며 움직임 종료 9–12초의 마지막 3초를 측정한다. 물리적 부력 복귀와 마지막 접촉 정리가 그 전에 없다는 뜻은 아니다.

60ml 저낙하 3개, 얼음을 먼저 넣고 입구로 실제 60ml를 붓는 순서, 8/12개 자동 업데이트, 실제 클릭 놓기, 가니쉬 표시 및 기존 도구·입력 회귀를 확인한다. 붓기 순서는 같은 엄격한 마지막 3초 기준을 두 연속 구간에서 확인하고, 관찰 완료 시간을 함께 기록한다. 첫 검사는 붓기 후 20초부터 시작하므로 최초 안정 시각을 측정한 값은 아니다. 초기 20초 고정 관찰에서 느린 정리 운동으로 실패한 기록도 보존한다.

`20261021-ice-hydrostatic-behavior`는 검증 사본 준비가 첫 실행과 겹쳐 최종 근거에서 제외한다. 그 밖의 실패한 수정안도 삭제하지 않는다. 최종 실행 선택과 SHA 검사는 아래 감사 파일에 기록했다.

## 남은 잔량 문제

비충돌 8개 자동 업데이트 최종 검사에서 흔들기 후 잔 안 잔량은 60ml 중 **55ml**였다. 같은 변경의 앞선 반복에서는 54.5ml도 관찰됐다. 총 액체량 보존 검사는 통과했지만 잔 안 잔량 유지가 완전히 해결된 것은 아니다. 얼음의 떨림·회전·이탈 기준은 해당 반복에서도 통과했다.

별도 [액체 단독 대조](20261021-ice-delivery-liquid-only/held-liquid-only-validation.txt)는 같은 자동 잔 이동을 두 번 수행해 모두 **60ml 유지**였다. 따라서 잔량 차이를 액체 단독의 기존 문제라고 확정할 근거는 없으며, 얼음이 포함된 상태의 상호작용에 대한 추가 추적이 필요하다. 이 항목은 미해결로 남긴다.
